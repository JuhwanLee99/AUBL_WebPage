# 제한된 외부 읽기와 업로드 검증 모듈

작성일: 2026-09-08

## 구현

`functions/scoring_test_io.py`에 실제 HTTP 및 업로드 스트림 제한을 수행하는 내부 모듈을 추가했다. 기존 NAS 호출이나 외부 endpoint에는 연결하지 않았다.

### 외부 읽기

- 별도 `SCORING_TEST_OUTBOUND_ENABLED=true`가 없으면 연결 전에 거부한다.
- 서버에서 설정한 origin·승인 경로 목록만 사용하며 GET만 지원한다. 임의 URL·query·인증 헤더를 클라이언트에서 받지 않는다.
- DNS 응답 전체를 검사한다. 로컬 모드는 loopback만, 운영 테스트 모드는 public global 주소만 허용한다.
- 검증한 숫자 IP에 직접 연결하여 연결 단계의 호스트 재해석을 피한다. HTTPS 인증서와 SNI는 승인된 원래 호스트 이름으로 검증한다.
- redirect를 따라가지 않고 200 이외 응답을 거부한다. 압축 응답도 거부한다.
- 명시된 응답 길이와 실제 읽은 바이트를 제한하고 연결을 항상 닫는다.

### 업로드

- 예상 크기와 SHA-256을 검사하고 스트림을 제한된 단위로 읽는다.
- 신고보다 긴 데이터, 짧은 데이터, 해시 불일치는 저장 후보로 넘기지 않는다.
- 검증 전 데이터는 임시 파일에만 보관하고, 성공한 경우에만 검증된 스트림을 context manager로 제공한다.
- 정상 종료·예외 모두 임시 파일을 닫아 정리한다. 영구 저장이나 공개 head 변경은 수행하지 않는다.

## 한도와 아직 남은 연결

모듈의 단일 응답·업로드 방어 상한은 16MiB다. 이는 임시 내부 자원 제한이지 확정된 경기 블록 규격이 아니다. 실제 블록 크기는 이 값 이하의 별도 승인값으로 설정해야 한다. 전체 경기 크기 제한이나 기존 단일 JSON 저장의 상한 확대로 사용하지 않는다.

소켓 timeout은 최대 15초의 비활성 시간 제한이며 요청 전체 wall-clock deadline은 아니다. 느린 스트림·동시 연결 수·요청 앞단 부하 제한은 실제 endpoint에서 추가해야 한다. 업로드 입력 스트림 역시 호출 계층이 읽기 timeout을 제공해야 한다.

현재 read transport는 origin·경로 제한만 수행한다. 실행 참여자·만료·중단 인가는 호출 직전에 별도로 필요하며, 실행 승인 해시 검증·공식 자료 내용 검증·NAS 임포트 방어를 대체하지 않는다. 환경 전체의 네트워크 sandbox도 아니다. 기존 서비스가 이 모듈을 우회하는 호출은 아직 남아 있다.

검증된 업로드의 실제 크기를 예약 서비스에 전달하고, 예산 승인 후에만 불변 저장을 수행하도록 다음 writer 통합에서 연결해야 한다. 임시 데이터 검증 자체가 실행 전체 예산을 자동 차감하지는 않는다.

## 검증 상태

최초 구현 후 아래 스텁 기반 검증을 실행했다. 실제 외부 네트워크 호출·운영 접속·배포는 실행하지 않았다.

실제 Auth·Functions·NAS 통합, writer 저장, 활성화는 미완료다. 운영 진입은 계속 `BLOCKED_BEFORE_LOGIN_BACKEND`다.
