# 선수 상세 파생 지표 계산 및 운영 반영

## 정책

원천 제공값이 존재하면 0을 포함하여 그대로 유지한다. 원천값이 null인 경우에만 확인 가능한 수집 항목으로 조회 시 계산한다. 계산 결과를 DB에 저장하거나 공식 원천 기록을 덮어쓰지 않는다.

| 지표 | 계산식 | 필수 원천값 |
| --- | --- | --- |
| K/9 | 탈삼진 × 27 / 아웃 수 | 탈삼진, 투구이닝, 확인된 이닝 표기 |
| BB/9 | 볼넷 × 27 / 아웃 수 | 볼넷, 투구이닝, 확인된 이닝 표기 |
| WHIP | (피안타 + 볼넷) × 3 / 아웃 수 | 피안타, 볼넷, 투구이닝, 확인된 이닝 표기 |
| AVG | 안타 / 타수 | 안타, 타수 |
| OBP | (안타 + 볼넷 + 사구) / (타수 + 볼넷 + 사구 + 희생플라이) | 식에 사용된 모든 항목 |
| SLG | (안타 + 2루타 + 2 × 3루타 + 3 × 홈런) / 타수 | 안타, 2루타, 3루타, 홈런, 타수 |
| OPS | 출루율 + 장타율 | 원천 제공 또는 계산 가능한 출루율·장타율 |

- UniquePlay의 `13.1`은 13.1이라는 십진수가 아니라 40아웃, `13.2`는 41아웃이다.
- 이닝 표기 계약이 확인되지 않은 과거 원천은 소수 이닝으로 파생 계산하지 않는다. 원천에 저장된 비율 값은 그대로 제공하며, 정수 이닝만 안전하게 계산한다.
- 필수 값의 누락, 음수, 분모 0, 모순된 안타 개수는 계산 불가로 남긴다. 누락된 사구나 희생플라이를 0으로 가정하지 않는다.
- 실제 탈삼진·볼넷 등이 0이고 분모가 양수이면 계산 결과 0을 정상 수치로 표시한다.
- 반올림은 HALF_UP이며 타격 비율과 WHIP는 소수 3자리, K/9·BB/9는 2자리이다. 기존 화면에서 WHIP는 2자리로 표시한다.
- OPS는 화면에 사용하는 소수 3자리 출루율·장타율의 합을 사용한다. 원천 제공 OPS가 있으면 덮어쓰지 않는다.
- ERA는 리그별 기준 이닝을 임의로 정하지 않으며 이번 자동 계산 대상에서 제외했다.

## 변경 위치

- 백엔드 `PlayerStatCalculations`: 읽기 전용 파생 계산.
- 백엔드 `PlayerRecordService`: 기존 선수 상세 DTO에 원천값 또는 계산 가능한 대체값을 연결.
- 프런트엔드 `getPlayerStats`: AVG, OBP, SLG, OPS, WHIP, K/9, BB/9의 null을 보존.
- 선수 상세 화면: 위 비율 항목이 null이면 실제 0과 구분해 `—`로 표시.

범위는 선수 상세 조회 경로다. 수집 워커, 기록허브의 순위 API, DB 저장 구조를 변경하지 않았다.

## 검증

- 프런트엔드 타입 검사와 배포 빌드 통과. 기존 번들 크기 경고는 남아 있다.
- 백엔드 220건 중 189건 통과, 실패 0건, 기존 조건부 통합 테스트 31건 제외.
- 신규 계산 테스트 9건: 정수 이닝, 1/3·2/3 이닝, 0이닝, 불명확한 과거 이닝, 음수·누락값, 실제 0, 제공값 우선순위, 타격 비율, 원천 엔티티 불변성.
- 실제 프런트엔드 API 모듈을 번들링하고 인증·네트워크만 대체한 변환 검사 21개 통과: 7개 비율 필드 × null/0/수치.
- 운영 API에서 김민수 7027은 K/9 18.00, BB/9 9.00, 이규석 7030은 K/9 15.53, BB/9 8.78 확인.
- 두 선수의 상세 응답은 위 누락 파생값 외의 기존 필드가 이전 응답과 동일함을 확인.
- 운영 브라우저 `/records/player/7027`에서 K/9 18.00, BB/9 9.00 표시 확인.
- 2025년 기록허브 전체 응답은 타자 1,507건, 투수 383건 모두 배포 전과 JSON 전체가 동일함을 확인. 이를 과거 전체 DB 불변성 검증으로 확대 해석하지 않는다.
- 테스트용 MariaDB 컨테이너와 전용 네트워크 정리 확인. 운영 DB에 테스트 데이터를 쓰지 않았다.

## 남은 구분

계산 불가한 비율 항목은 추정하지 않는다. 원천에 없는 집계 항목 전체를 새로 수집하거나 경기별 로그를 재합산하는 작업, ERA 기준 프로파일 추가, 모든 기록 화면의 null 표시 통합은 이번 범위가 아니다.
