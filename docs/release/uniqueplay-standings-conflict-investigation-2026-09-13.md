# 순위 충돌 후속 분석

날짜: 2026-09-13 KST

상태: `CAUSE_NOT_CONFIRMED_FIX_APPROVAL_PENDING`

## 확인한 사실

- 대상 실패 실행: `b73b01e3-414a-48c4-873a-7dc3bc62aaab`, `STANDINGS_RANK_CONFLICT`.
- UniquePlay 리그 57의 기록 > 2026시즌 > A조 > 팀순위를 브라우저로 다시 조회했다.
- 현재 원천은 동국대 1위(5승 1패 2무), 고려대 1위(5승 1패 1무), 한양대 에리카 3위(3승 2패 1무), 경희대 서울 4위(1승 5패), 서경대 5위(1승 6패)다.
- 실제 DOM에 현재 워커와 같은 고정열/수치열 추출 방식을 적용했을 때 5팀의 순위와 승패무가 일치했다.
- 이것은 현재 브라우저 관측이며, 실패 당시 워커가 읽은 DOM의 복원 결과는 아니다.

## 코드에서 확인한 경계

1. `services/uniqueplay-sync-worker/src/adapter.mjs`의 `collectUntilStable`은 `row.fixed.join('|')`를 누적 행 키로 사용한다. 팀순위에서 순위가 바뀌면 같은 팀도 새 행으로 추가된다.
2. 안정화 여부는 누적 행 개수가 증가하지 않는지만 판단한다. 같은 키의 수치가 계속 바뀌어도 내용 변화 자체는 안정화 카운터를 초기화하지 않는다.
3. `collectGroup`은 오류 객체의 메시지에는 조 정보를 넣지만, `durable-runs.mjs`의 오류 전달 경로는 안전한 코드만 기록한다. 따라서 현재 운영 로그만으로 충돌 조, 충돌 유형, 비교 수치를 특정할 수 없다.
4. 순위 검사 자체를 제거하거나 원천 순위를 임의 재계산하는 것은 해결책으로 채택하지 않는다.

## 합성 재현의 결과와 한계

- 첫 읽기에서 모든 순위를 1로 주고, 후속 읽기에 현재 정상 원천의 순위 1·1·3·4·5를 주는 합성 시퀀스를 실행했다.
- 실제 오류의 수집 행 수는 8행으로 나타났다. 5팀의 변경 전/후 행이 별개로 누적될 수 있음을 확인했다.
- 다만 재현 입력의 스크롤 결과에 `advanced: false`가 빠져 `reachedCollectionEnd` 계약을 충족하지 못했다. 실행은 `COLLECTION_INCOMPLETE`로 종료됐으며, 최종 `auditStandings` 결과는 얻지 못했다.
- 이 합성 사례를 이번 운영 실패의 원인 확정이나 성공한 회귀 테스트로 계산하지 않는다.

## 권장 후속 작업

1. 재현 입력의 스크롤 완료 계약을 바로잡고, 순위 변동과 같은 길이 수치 변동을 독립 회귀 사례로 고정한다.
2. 팀순위 수집에 순위와 독립적인 팀 식별 및 내용 안정화 판정을 적용한다. 실제 동일 시점 중복 팀, 가상 스크롤 누락, 미완성 표를 임의 병합하거나 통과시키지 않도록 검사한다.
3. 순위 실패 진단에 허용된 조 코드, 행 위치, 숫자 수치, 검증 코드만 제한적으로 보존한다. 임의 오류 메시지, DOM 전체, 계정 정보는 출력하지 않는다.
4. 워커 회귀 검증 후 별도 이미지 배포와 새 수집을 통해 운영 실패 원인을 대조한다. 새 후보가 생성되기 전까지 팀명 매칭의 운영 개선 효과는 미검증이다.
