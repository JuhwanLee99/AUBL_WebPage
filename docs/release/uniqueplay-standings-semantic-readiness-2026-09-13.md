# 순위 의미 검증 기반 재확인 보완

> 후속 상태: 2026-09-13 14:25 KST 워커 18 운영 배포 후 증분 수집과 서버 검증이 통과했다. 후보는 게시하지 않았으며 49경기의 83개 검수 경고가 남았다. 아래 운영 미배포 설명은 로컬 구현 당시 기준이다. 최신 결과는 `uniqueplay-semantic-worker-deployment-2026-09-13.md`를 따른다.

## 범위와 현재 운영 상태

이 문서는 워커 17 배포 이후 발견한 지연 렌더 경계의 로컬 보완을 설명한다. 운영에는 워커 17이 남아 있으며, 본 변경의 배포·실제 재수집·공식 게시·활성화는 수행하지 않는다. 로컬 테스트 통과만으로 운영 실패 원인이 해결됐다고 판단하지 않는다.

운영 실패 `1be683f3-3ee0-431a-b37b-d71347fcf1a5`는 A조 5개 팀을 모두 1위로 수집했다. 실패 후 원본 화면은 `1,1,3,4,5`였다. 실제 순간의 원본 DOM은 없어 동일 원인을 확정할 수 없다.

## 재현과 확인한 사실

- 숫자 정규화 및 실제 `standingFromRow` 변환은 입력 순위를 보존한다. 별도 변환 회귀 5건에서 확인했다.
- 원본과 같은 래퍼 구조를 갖는 합성 HTML에서 실제 `readVisibleTable`도 정상 순위를 보존했다.
- 실제 `collectVirtualTable`에 순위 렌더 완료를 두 번째 대기 시점으로 설정하면 정상 순위가 수집된다.
- 렌더 완료를 여섯 번째 대기 시점으로 늦추면 기존 수집기는 세 번 대기 후 모두 1위인 표를 반환했다. 표의 구조적 안정과 기록 값의 준비 완료는 다르다.
- 이는 합성 경계 재현이다. 운영 원천 DOM을 저장·재생한 테스트 또는 실제 경기 표본으로 계산하지 않는다.

## 선택한 방식과 대안 비교

| 방안 | 판단 |
|---|---|
| 모든 표에 긴 고정 대기 추가 | 정상 수집도 느려지고 필요한 지연 시간을 보장하지 못해 제외 |
| 승률로 순위 재작성 | 원천 공동 순위와 타이브레이크를 변조할 수 있어 제외 |
| 충돌 검증 해제 또는 경고만 남기기 | 잘못된 공식 후보가 통과할 수 있어 제외 |
| 수집 전체를 무제한 재실행 | 인증·콜백·저장 장애까지 숨기며 실행 종료를 보장하지 못해 제외 |
| 불일치한 순위 표만 제한적으로 다시 읽기 | 원천 값을 보존하고 기존 검증기를 재사용하므로 채택 |

## 구현 계약

`collectReadyStandings`가 완성된 원시 표를 읽고 실제 변환 함수를 적용한 뒤 기존 `auditStandings`로 검사한다. 정상 표는 첫 시도에 반환한다. 순위·승패 모순이 있으면 500ms 대기 후 같은 조의 표를 새로 수집한다. 기본 최대 4회이며 설정 허용 범위는 1~6회다.

여기서 횟수는 **표 수집 횟수**다. 각 표 내부의 기존 스크롤·준비 대기 제한은 별도로 적용되므로 전체 소요 시간을 1.5초 또는 고정된 몇 초로 보장하지 않는다. 클릭·조 선택·인증·전체 실행 접수를 반복하지 않는다.

최종 실패는 기존 `standingsConflictError`를 사용한다. 행이 없거나 표 결과가 배열이 아니면 `STANDINGS_TABLE_INCOMPLETE`로 즉시 거부한다. 읽기·인증·저장·변환·대기 오류는 잡아서 다시 시도하지 않고 원래 오류를 전파한다. 페이지가 닫히면 대기나 다음 읽기에서 중단된다.

어댑터의 `collectGroup` 순위 수집에 연결했으며 후속 기존 순위 검증도 유지한다. 타자·투수 표 수집, 공식 원천 정책, 콜백/ACK 계약, 배포 설정은 변경하지 않는다.

## 진단과 개인정보 경계

재확인이 필요한 시도마다 `event=standings_readiness` 로그를 남긴다. 다음 값만 허용한다.

- A~H 조 코드, 고정 표 종류, 시도 번호와 상한, `waiting/recovered/rejected` 상태.
- 동일 표본의 원시 순위와 변환 후 순위. 숫자 또는 null로 제한하며 각각 최대 40행이다.
- 행 수, 절단 여부, 허용된 순위 검증 코드.

팀명·선수명·URL·인증정보·원시 HTML·임의 오류 메시지는 기록하지 않는다. 로그의 원시·변환 순위 비교로 DOM 수집값 자체가 잘못됐는지 변환 후 달라졌는지 구분한다. 이 로그는 컨테이너 로그이며 새로운 영속 이벤트 계약을 추가한 것은 아니다. 최종 실패의 기존 구조화 진단과 콜백 보존 경로는 그대로 사용한다.

## 회귀 검증 범위

단위 테스트는 정상 즉시 반환, 공동 순위 보존, 초기 모순 후 회복, 역전 순위·빈 순위·잘못된 승패, 최종 시도 회복, 영구 충돌 차단, 원시/변환 진단 구분, 개인정보 배제, 최대 행 제한, 인증·저장·UI·수집 오류 전파, 변환/페이지 종료, 빈 표 차단, 잘못된 횟수 설정, 무승부만 있는 무결정 표, 원본 불변성을 다룬다.

브라우저 테스트 4개는 외부 요청을 차단한 로컬 Chromium에서 실제 DOM 추출과 가상 스크롤 수집기를 사용한다. 정상 표, 초기 안정화 도중 정상화, 초기 안정화 이후 정상화, 끝까지 모순된 표를 구분한다. 대기 시점은 결정적으로 제어하므로 실제 네트워크 지연 시험을 대체하지 않는다.

실행 명령:

```sh
node --test test/*.test.mjs
node --test test/browser/*.test.mjs
```

전체 결과의 pass/fail/skip은 `docs/release/evidence/uniqueplay-standings-semantic-readiness-2026-09-13/`에 저장하는 TAP 원본을 기준으로 판정한다. 기존 실패 증거는 덮어쓰지 않는다.

## 후속 운영 검증

1. 로컬 전체 회귀 결과를 확인하고 새 이미지 업로드·배포 절차로 진행한다.
2. NAS 백업, 활성 실행과 큐 0건, 설정 보존을 확인한 후 워커만 교체한다.
3. 기본 증분 수집 1회에서 A조를 포함한 전체 조와 이전 일반 수집 오류 경계 통과를 확인한다.
4. 실패하면 같은 표본의 원시/변환 순위와 재확인 추이를 조사한다. 검증기를 우회하거나 무작정 재수집하지 않는다.
5. 성공해도 후보 변경·삭제 내역과 경기 상세 경고를 검토하고 서버 검증한다. 공식 게시·활성화는 별도 승인이다.
