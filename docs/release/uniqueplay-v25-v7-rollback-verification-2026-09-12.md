## 시험 구성

실제 배포용 신규 이미지 → 기존 v25 이미지 → 신규 이미지 순서의 3단계 시나리오다. 성공한 단계만 위 완료 목록에 포함한다. 세 단계 모두 기동·조회·동일성 확인을 완료했다.

새 버전의 기존 전체 흐름 테스트로 MariaDB 11.8.5의 V7 DB에 합성 수집·게시 데이터를 만든다. 여기에 범위 컬럼이 NULL인 구형 형태의 run 1건을 추가한다. 이 NULL 행은 V7 적용 후 만든 호환 자료이며 운영에서 이관한 행이 아니다. 실제 마이그레이션 이전 행의 보존 시험과 구분한다.

각 배포 이미지의 원래 JAR·기본 진입점을 사용한다. Firebase 서비스 계정 파일은 로컬에서 만든 가짜 RSA 키와 demo 프로젝트만 사용하며 운영 자격 증명이 아니다. Auth 에뮬레이터에서 발급한 관리자 ID 토큰으로 실제 보안 필터·HTTP API를 통과한다.

Flyway 이력 삭제·repair·future migration 무시 옵션의 추가 없이 실행한다. Hibernate DDL은 none이며 운영의 PhysicalNamingStrategyStandardImpl을 유지한다. 네트워크는 Docker internal이고 호스트 포트를 공개하지 않는다.

## 통과 조건

- 각 버전의 기동 및 익명 관리자 요청 거부.
- 범위 값이 있는 run과 NULL인 run 등 3건을 관리자 API로 읽고 DB의 checksum·상태와 대조.
- 각 run의 경기 기록 검수 API를 읽고 검수 checksum 및 공통 응답을 신규 버전 기준선과 비교.
- 각 단계 종료 후 전체 합성 DB 논리 덤프를 바이트 단위로 비교하여 원본·범위 컬럼·Flyway 이력 등 불변 확인.
- Firestore의 공식 메타데이터와 경기 2건을 기존 활성 revision 및 최초 응답과 비교.
- 임시 컨테이너·네트워크 및 가짜 서비스 계정 파일 정리.

## 판정 한계

이 시험은 읽기 전용 복귀와 신규 버전 재기동의 호환성이다. v25의 신규 수집·정정·게시·활성화는 수행하지 않으며 구형 writer를 다시 허용하는 근거가 아니다. 운영 데이터에 대한 백업 복원, 장애 중 부분 마이그레이션 복구, 공식 리비전 변경 복구, NAS·원천 수집 성공 및 RPO/RTO를 검증한 것이 아니다.

통과하더라도 기존 run과 쓰기 차단을 유지한 채 읽기 복귀를 검토할 수 있을 뿐, 운영 백업·설정·정확한 롤백 대상과 별도 승인이 필요하다. 운영 API·DB 접근, push·배포는 하지 않았다.
