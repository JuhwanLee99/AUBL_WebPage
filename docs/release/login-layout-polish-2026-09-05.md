# 로그인 페이지 레이아웃 정리

## 확인한 문제

- 사용자 Chrome의 기존 `/login` 탭에서 소개 카드 상단의 큰 빈 공간, 하단으로 밀린 제목, 혼재한 카드·버튼 모서리와 보조 안내 배치를 확인했다.
- `LoginPage.css`의 전용 디자인에 `index.css`의 이전 로그인 스타일과 `season-detail-scope` 보정 스타일이 동시에 적용됐다. 공통 CSS의 순서·우선순위가 전용 디자인의 색상·형상·타이포그래피를 덮어쓰는 구조였다.
- 소개 영역의 고정 최소 높이·하단 정렬이 폼 높이에 따라 과도한 공백을 만들었다.

## 변경 내용

- 이전 공통 로그인 CSS를 제거하고 `LoginPage.css`에서 로그인 화면의 레이아웃을 완결적으로 정의한다.
- `/login`과 `/login/`만 기존 상세 페이지 보정 스타일에서 제외한다. 다른 상세 페이지와 공통 내비게이션·헤더·푸터는 유지한다.
- 데스크톱은 최대 1080px 안에서 왼쪽 소개·보조 안내, 오른쪽 최대 440px 로그인 폼으로 정렬한다. 고정 높이·하단 정렬을 제거하고 양쪽 상단을 맞춘다.
- 900px 이하에서는 소개 → 로그인 폼 → 보조 안내 순서의 단일 열로 전환한다.
- 제목 문구를 유지하면서 줄 단위와 한국어 단어 줄바꿈을 정리한다.
- 탭·입력창·로그인·소셜 버튼의 너비와 간격, 4px 모서리, 최소 48px 입력/버튼 높이를 통일한다. 입력 글자는 16px로 유지한다.
- 라이트/다크에서 공통 시즌 토큰을 사용하며, 다크모드 제출 버튼 hover의 글자 대비도 보강한다.
- 자동완성 입력 배경·글자색, 긴 오류 메시지 줄바꿈, 키보드 포커스, 선택 버튼의 `aria-pressed`, 폼 이름·오류 알림을 정리한다.
- Flutter 임베디드 로그인에 안전영역 여백을 추가하고 동의 모달 배경·좁은 화면 버튼 폭을 조정한다.

## 유지한 기능과 안전 범위

- 이메일 로그인, 회원가입 동의·비밀번호 확인, Google/Apple 처리, 리디렉션, 기존 Flutter 메시지·인증 계약을 변경하지 않는다.
- 인증 처리 함수와 약관·개인정보 처리방침 내용은 변경하지 않는다.
- 운영 로그인 탭은 관찰만 했다. 입력 내용을 수정하거나 로그인/가입을 제출하지 않았으며 새 사용자 Chrome 탭을 만들지 않았다.
- 테스트는 실제 Layout와 LoginPage를 사용하되 인증·스토어·브리지는 무해한 fixture로 대체했다. 실제 계정 생성·삭제·외부 인증 호출은 하지 않았다.
- NAS 백엔드, DB, UniquePlay, 기록원 입력·저장 기능 및 Flutter 앱 소스는 변경하지 않는다.

## 검증

- `npm run test:login-layout`: 23개 통과.
  - 320·360·390·768·900·960·1280·1920px × 라이트/다크에서 로그인·회원가입 정렬 및 가로 넘침
  - CSS 로드 순서 변화에도 전용 스타일 유지
  - 버튼 기본/hover 대비 4.5:1 이상, 최소 44px 터치 영역, 16px 입력 글자
  - 키보드 포커스, 자동완성 속성, 이메일 리디렉션, 회원가입 필수 동의·확인 입력
  - Google/Apple 기존 처리 경로와 긴 오류 메시지
  - Flutter 임베디드 모드의 소셜 노출 조건·동의 모달·Escape 및 포커스 복귀
  - 200% 텍스트 확대, 모션 감소
- 기존 홈 테스트 35개 통과 (`test:home-hero` 8, `test:home-matches` 13, `test:home-freshness` 14). 총 58개 통과.
- 타입 검사, 변경 TSX ESLint, 프로덕션 빌드, `git diff --check` 통과. 기존 번들 크기 경고는 남아 있다.
- fixture의 360px 라이트와 1280px 다크 화면 이미지를 열어 배치·줄바꿈을 확인했다.
