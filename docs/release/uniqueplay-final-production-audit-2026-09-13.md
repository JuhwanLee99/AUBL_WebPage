## 판정

**현재 공개 조회·관리자 인증·수집 중단은 정상이다. 그러나 무조건적인 운영 승인 또는 무인 재배포 승인은 보류한다.**

운영 데이터 쓰기, 신규 수집, 후보 게시, 공식 활성화, 컨테이너 재시작·재배포 없이 점검했다. 제품 코드와 운영 설정은 변경하지 않았다. 이전 테스트 통과 수를 이번에 다시 실행한 결과로 계산하지 않는다.

## 확인한 문제

### F01 / P1: TrueNAS 원본 설정과 실제 배포 설정 불일치 위험 미해결

이전 배포에서 TrueNAS 원본 앱 설정은 구형 이미지/DB를 가리키고 Portainer에서만 최신 실행 설정을 적용한 것으로 기록돼 있다. 이번 Portainer 점검에서는 최신 이미지와 동일 컨테이너가 계속 실행 중임을 확인했다. 그러나 `http://172.30.1.33/ui/dashboard`는 `ERR_ADDRESS_UNREACHABLE`로 접속되지 않아 원본 설정이 이후 수정됐는지 확인하지 못했다.

- 영향: TrueNAS 앱 업데이트·재배포가 이미지, DB 연결, 환경 변수를 이전 값으로 되돌릴 수 있다.
- 판정: 이미 롤백됐다는 뜻이 아니라, 앞서 확인된 설정 불일치의 해소를 입증하지 못했다는 뜻이다.
- 권장: 원본 앱 정의에 현재 이미지 digest, DB `aubl`, CORS, 워커 연결, 영속 콜백 설정을 반영하거나 배포 관리 주체를 명시적으로 통일한다. 그전에는 TrueNAS 앱 재배포를 하지 않는다.

근거: `uniqueplay-cancellation-production-deployment-2026-09-13.md` 7절, 이번 Portainer 실행 목록 및 TrueNAS 접근 실패.

### F03 / P2: SPA 진입 HTML에 1시간 캐시 적용

실제 `/`와 `/admin/unique-play-sync`의 응답은 모두 `Cache-Control: max-age=3600`이었다. 최신 번들은 현재 제공되고 있으나, 이미 캐시된 진입 HTML을 가진 클라이언트는 배포 직후 이전 번들을 계속 사용할 수 있다.

- 원인 근거: `firebase.json:33`은 `**/index.html`만 `no-cache`로 설정한다. `firebase.json:53`의 SPA rewrite 대상인 원래 요청 경로까지 같은 정책이 적용되지 않고 있다.
- 영향: 긴급 수정이나 백엔드 계약 변경 뒤 구형 관리자 UI가 한동안 남을 수 있다. 이번 점검에서 실제 구형 화면을 재현했다는 뜻은 아니다.
- 권장: SPA HTML 요청 전체에 재검증 정책을 적용하고 해시 자산의 장기 immutable 캐시는 유지한다. `/`, 관리자 경로, 일반 상세 경로의 실제 응답 헤더를 배포 후 확인한다.

### F04 / P2: 배포 증거의 체크섬 판정 필드가 실제 의미와 불일치

기존 `evidence/uniqueplay-cancellation-2026-09-13/deployment-manifest.json`의 `publicAfterCancellation.officialChecksumPreserved`는 `false`다. 그러나 비교 대상 공개 API는 전체 체크섬을 제공하지 않는다. 문자열이 없다는 관측을 체크섬 보존 실패로 이름 붙여 저장한 것이다.

- 영향: 자동 결과 취합기가 정상적인 배포를 데이터 변경 사고로 오판할 수 있다. 문서의 해설만으로는 기계 판정을 바로잡을 수 없다.
- 권장: 원시 프로브를 보존하되 판정을 `not_checked` 또는 `null`과 `checksum_not_exposed` 사유로 분리한다. 체크섬이 실제 제공되는 별도 원천을 확인했을 때만 일치·불일치를 판단한다.
- 이번 처리: 문제를 확인하고 기록했다. 기존 결과 파일이나 검사 코드를 승인 없이 수정하지 않았다. 현재 공식 리비전 일치는 확인했지만 전체 내용 체크섬 일치까지 확인한 것으로 주장하지 않는다.
