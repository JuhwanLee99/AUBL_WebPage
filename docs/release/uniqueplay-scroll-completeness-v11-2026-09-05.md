# UniquePlay 수집 완전성 수정 — 워커 v11

## 장애와 영향

2026-09-05 실행 `0093edba-f02e-4f64-aee1-bd781d666b95`는 16:15:34 KST에 시작해 16:24:37 검증 실패 상태가 됐다. A~H 40팀에 `GAME_COUNT_MISMATCH`가 발생했다. 서경대학교 JUKSITA 2 : 7 동국대학교 L.A.E(9월 5일 09:00, 서울대공원야구장, `up-9f98016e1baa617ad7b824cc`) 자체는 종료 결과로 수집됐다.

v10은 게임 결과의 첫 지연 로딩 묶음 8개 중 A~H 경기 6개만 읽었다. 나머지 2개는 올스타 경기라 기존 범위 필터에서 제외됐다. 원천 목록을 실제로 스크롤하면 이전 경기가 추가로 나타나는 것을 Chrome에서 읽기 전용 확인했다. 원천의 이전 경기가 삭제된 상황이 아니다.

실패 후보에는 경기 112개와 경기 상세 112개가 삭제 후보로 나타났다. 전체 삭제 후보 643개 중 나머지 419개는 기존 누적 기록 식별·규정 IN/OUT 등과 별도 대조해야 하며 이번 스크롤 장애가 전부의 원인이라고 단정하지 않는다. 삭제 후보 표시는 실제 삭제가 아니다. 검증 차단은 정상적으로 공개 데이터를 보호했다.

진단 시 공개 리비전은 `375df8a9-5f3b-49f6-81a6-cc26906c4465`였다. 실패 후보를 강제 게시하거나 검증 오류를 경고로 낮추지 않는다.

## 원인

`scrollPageList()`가 `scrollHeight > clientHeight`인 가장 가까운 조상을 선택하면서 CSS `overflow-y`를 확인하지 않았다. 실제 카드 높이는 192px, 내용 높이는 214px, `overflow-y: visible`이었다. 이 카드는 스크롤할 수 없는데도 수집기가 이 요소를 선택해 `scrollTop`을 변경했다. 그 결과 이동 없음과 3회 동일 행을 목록 끝으로 오인했다.

실제 목록은 그 위 조상의 `overflow-y: auto`, 높이 1120px, 내용 높이 1683px 요소였다. 같은 높이 비교 방식이 시즌 누적 표에도 있어 공통으로 보완한다.

## v10 → v11 변경

- 어댑터 `2026.09.05.10` → `2026.09.05.11`.
- 공개 날짜·표 헤더를 기준으로 `auto/scroll` 세로 스크롤 영역을 탐색한다. `visible/hidden/clip` 카드와 세로 넘침 없는 가로 스크롤 래퍼는 실제 세로 목록을 가리지 않는다. 문서 전체 스크롤과 화면에 모두 들어오는 작은 목록도 처리한다.
- 스크롤 이동과 끝 위치를 별도로 반환한다. 끝이 아닌 곳에서 이동이 멈추거나 목록 구조가 사라진 경우 3회 반복만으로 완료하지 않는다. 최대 시도 내 끝 위치와 안정화를 증명하지 못하면 `COLLECTION_INCOMPLETE`로 중단한다.
- 목록·표 샘플 간 대기를 120ms에서 500ms로 늘리고, 대기 후 다시 읽은 결과를 기준으로 3회 안정화를 판정한다. 경기 상세 카드 탐색에도 같은 스크롤 선택을 적용한다.
- 상세 수집 전, 원천 순위표의 조별 팀 경기 수 합계와 **결과 탭에서 수집한** 종료 경기 수를 대조한다. 일정 탭의 이전 종료 값, 중복 행, 예정·취소 경기로 누락을 채우지 않는다. 부족하면 후보 업로드 전 실패 콜백만 보낸다.
- 사전 검사는 특정 시즌 경기 수를 하드코딩하지 않으며 팀명 별칭을 추정하지 않는다. 조별 합계의 하한 확인일 뿐 모든 경기의 정확성 증명은 아니다. 기존 서버의 팀별 경기 수·상세·점수·매핑·개인정보 검증은 유지한다.
- `/health`와 시작 로그에 공개 어댑터 버전을 표시해 배포본을 확인할 수 있게 한다. 인증·비밀값·세션 원문은 추가 노출하지 않는다.
