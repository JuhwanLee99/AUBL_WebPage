# 2026 선수 누적 기록 누락 복구

## 확인한 경로

- 워커는 A~H조 타자/투수의 규정 IN/OUT 표를 모두 수집한다.
- 백엔드는 승인된 리비전 활성화 시 Player, TeamPlayer, BatterStats, PitcherStats를 생성/갱신한다. 같은 시즌/팀/선수의 기존 행을 재사용한다.
- 공개 순위 API는 활성 리비전에 귀속된 기록만 반환한다. 기록허브는 숫자가 전부 null인 행을 숨긴다. 이 필터를 제거하거나 null을 0으로 표시해서 복구하지 않는다.
- 운영 API에서 2026 seasonId=12 선수 ID와 이름은 존재하지만 통계가 null인 사례를 확인했다. 최신 실행 7a01e409-cef7-4877-a61f-a2b5e69d57f0은 조사 시 이미 활성화 완료 상태였다.

## 원인과 수정

유니크플레이 개인순위의 값 행은 바깥 행, 중간 래퍼, 숫자 셀 행으로 중첩되어 있다. 기존 readVisibleTable은 바깥 행의 직계 자식을 셀로 간주하여 숫자를 연결한 한 문자열로 수집하고 나머지 통계를 null로 만들었다. 선수 이름과 DB 항목은 생성되어도 기록 수치가 누락되는 구조다.

수정 버전 2026.09.22.1은 제한된 깊이에서 헤더와 같은 열 수를 갖는 유일한 숫자 행을 찾는다. 중복 후보, 열 누락/추가, 숫자가 아닌 값, 전체 빈 행은 거부한다. 고정 선수 행과 숫자 행의 개수 불일치도 잘라내지 않고 실패한다. 기존 직접 셀 구조와 0 기록은 유지한다.

## 복구 원칙

기존 원본을 직접 덮어쓰지 않고 수정 워커로 새 증분 수집을 수행한다. 증분 모드에서도 선수 시즌 누적은 전체를 수집하므로 과거 경기 상세를 모두 다시 읽을 필요는 없다. 새 후보의 수치, 충돌, 삭제 후보를 검토한 후 공식 게시/활성화를 진행해야 공개 DB와 기록허브에 반영된다. 2025년과 다른 시즌은 수정하지 않는다.

### 공개 API와 화면 확인

- 인증정보 없는 공개 API의 `seasonId=12&regulation=ALL&limit=0` 조회에서 타자 937건, 투수 266건을 확인했다. 이는 각 종류의 시즌 기록 행 수이며 두 종류를 합한 고유 선수 수가 아니다.
- 반환된 타자·투수 행 각각에서 해당 API의 통계 필드가 전부 null인 행은 0건이다. `playerId/teamId/seasonId/scope/group` 조합의 중복 행도 각각 0건이다. 원천 기록의 모든 수치가 정확하다는 의미는 아니다.

- 이규석 선수는 기존 `playerId=7030`을 유지했다. 4경기, 13.1이닝, 23탈삼진, 2승, ERA 5.25, WHIP 1.88이 원천 표와 일치한다.

- 기존 경기 상세의 원천 합계·실점·자책 등 경고는 이번 선수 누적 수집 복구와 구분한다. 경고를 숨기거나 원천 수치를 임의 수정하지 않았으며, 경고를 확인한 상태로 게시했다.
