# 최종 점검 후 운영 보완 결과

기준: 2026-09-13 KST. 사용자 결정: 운영 관리는 Portainer만 사용하고 나머지 점검 항목을 해결한다.

## 1. 확정한 운영 방침

- 백엔드와 워커의 이미지 교체, 환경 변수, 마운트 및 재시작은 Portainer에서 관리한다.
- TrueNAS 앱 UI를 이용한 해당 앱의 업데이트·재배포는 사용하지 않는다. TrueNAS는 NAS/스토리지 관리 용도로 유지한다.
- 변경 전 현재 컨테이너 설정과 이미지 digest, DB 백업, 워커 상태 디렉터리를 확인한다. 동일 상태 디렉터리를 두 워커가 동시에 소유하지 않는다.
- 이번 결정은 운영 절차의 일원화다. 기존 TrueNAS 앱 정의를 삭제하거나 기술적 소유권을 이관하거나 자동 재배포를 차단한 작업은 아니다. TrueNAS 재배포를 실행하면 과거 설정으로 되돌아갈 위험은 여전히 있으므로 금지 절차를 준수한다.
- 이번에는 백엔드·워커 이미지를 다시 교체하지 않았다.

## 2. 완료: HTML 캐시 수정 및 운영 배포

`firebase.json`의 기본 HTML 캐시 규칙을 `**/index.html`에서 `**`로 확장했다. 뒤에 정의된 해시 자산 규칙은 기존 장기 immutable 캐시를 유지한다.

기존 검증 산출물 `/tmp/aubl-cancellation-web.VJVfve/workspace/dist`에 새 Hosting 정책만 적용해 `aubl-backup`에 배포했다. 소스 번들을 임의로 다시 빌드하거나 Functions/Firestore 규칙을 함께 배포하지 않았다.

실제 운영 응답:

| 요청 | 상태 | Cache-Control |
| --- | --- | --- |
| `https://aubl.club/` | 200 | `no-cache` |
| `https://aubl.club/admin/unique-play-sync` | 200 | `no-cache` |
| `https://aubl.club/assets/index-gUm72q18.js` | 200 | `public,max-age=31536000,immutable` |

이미 브라우저에 저장된 구형 HTML의 기존 만료 시각을 원격으로 소급 변경한 것은 아니다. 새 응답부터 재검증 정책이 적용된다.

## 5. 추가로 확인한 게시 전 보완 사항

### 조별 순위 비교 UI 누락

`GROUP` 8건 모두 변경으로 분류되지만 비교 화면은 `세부 필드 변경 없음`으로 표시한다. 현재 UI로는 바뀐 순위를 직접 검수하기 어려워 이번에는 저장 후보 JSON을 별도로 대조했다.

후속 보완: `src/features/sync/components/UniquePlayDiffTable.tsx`에서 그룹의 순위 배열을 팀 식별 기준으로 비교하고 기존 순위·원천 순위·승패를 표시한다. 데이터가 누락된 경우 변경 없음으로 오인시키지 않아야 한다.

### 팀 이름 표기에 따른 동일 선수 기록의 추가·삭제 분리

실제 추가/삭제 후보에서 같은 선수·같은 구분의 다음 식별자 쌍을 확인했다.

| 선수 | 삭제 후보 팀 표기 | 추가 후보 팀 표기 |
| --- | --- | --- |
| 김지후 | 한양대ERICA HIBA | 한양대학교 에리카 HIBA |
| 홍경민 | 동국대학교 LAE | 동국대학교 L.A.E |
| 김인호 | 서경대학교 적시타 | 서경대학교 JUKSITA |

외부 ID가 `조|BATTER|IN/OUT|정규화한 팀명|선수명` 형태여서 이름 표기 변경이 기록 삭제·추가로 나타난다. 확인한 쌍은 기존 팀 매핑을 활용해 동일 기록의 변경으로 연결할 필요가 있다. 삭제 후보 438건 전부가 같은 원인이라고 전수 확인한 것은 아니다. IN/OUT 자격 구분 변화는 이름 변경과 별도 판정해야 한다.

후속 보완: 불변 팀 매핑을 기준으로 비교하고, 매핑이 모호하거나 일대다인 경우 자동 병합하지 않고 검수 대상으로 남긴다. 기존 후보는 원본 증거로 보존하고 서버의 공식 정정/재검수 경로를 사용한다. 운영 DB를 직접 수정하지 않는다.

### 경기 상세 경고

자책점이 실점보다 큰 값, 타자 득점 합계 불일치, 투수 피안타 합계 불일치, 이닝 점수 불일치 등이 표시된다. 서버 검증 통과가 이 경고의 해소를 뜻하지 않는다. 신규 상세와 보존된 과거 상세를 구분하고 원천 오류인지 수집 변환 오류인지 대조해야 한다.
