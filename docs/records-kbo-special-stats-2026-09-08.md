# KBO 모달 기록 추가 보강: 실책 세이프 도루자와 DP/TP

작성일: 2026-09-08

## 범위와 운영 경계

로그인 및 운영 백엔드 연동 전, 로컬 기록 엔진과 실제 모달의 기록법 예외를 보강했다. 운영 경기 생성, 운영 데이터 저장·삭제, 배포는 하지 않는다. 로그인·백엔드 진입 게이트는 계속 `BLOCKED_BEFORE_LOGIN_BACKEND`다.

이번 변경은 기존 잠정 기록과 유니크플레이 공식 기록의 공개 정책을 변경하지 않는다. 수비 통계는 사건별 수비 위치에 귀속되며, 교체 이력을 반영한 선수별 수비 통계 원장까지 완성한 것은 아니다.

## 규칙 근거와 판단

근거는 [KBO 2025 공식 야구규칙](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2025_%EC%95%BC%EA%B5%AC%EA%B7%9C%EC%B9%99.pdf)의 공식기록 조항이다. 2026년 전체 규칙과 개정 차이의 검증을 완료했다는 의미는 아니다.

| 근거 | 기록상의 구분 | 구현 판단 |
| --- | --- | --- |
| 9.07(d), (f) | 정확한 송구를 놓쳐 도루자가 살아난 경우 CS·E·A를 기록하며, 동시 도루의 다른 주자에게도 SB를 부여하지 않는 경우가 있다. | 실제 아웃과 CS를 분리하고 도루 시도 그룹으로 SB·CS를 계산한다. |
| 9.02(a)(17) 주석 | 첫 아웃 후 두 번째 아웃용 정확한 송구의 포구 실패도 병살타 기록 대상이다. 주자 방해로 타자가 아웃된 경우와는 구분한다. | 미완성 GDP를 명시적으로 입력하며 실제 아웃은 하나, 수비 DP는 미부여한다. |
| 9.10, 9.11 | 보살 및 연속 수비의 DP/TP 참여는 실제 아웃 수나 GDP와 별개다. | 보살 경로와 완료된 아웃을 사용하고 참여 야수별 DP/TP를 한 번씩 부여한다. |

## 설계 및 구현

### 1. 실책으로 세이프가 된 도루자

- 기존 주루 행의 `cause: caught`를 사용하되 결과를 다음 베이스 또는 홈 도달로 입력할 수 있게 했다.
- 포구 실책, 실책 설명, 송구 보살 경로, 판정 근거를 필수로 연결한다. 악송구를 이 예외로 간주하지 않는다.
- 세이프 행에 자살·아웃 종류·타점을 동시에 지정하거나 타자에게 CS를 부여하는 입력은 거부한다.
- 코어에는 실책 진루로 전달해 실제 아웃을 늘리지 않고, 결과에는 원래 사건과 근거를 유지한다.
- 동일 주자의 동일 `stealGroup`에서 세이프 뒤 다시 아웃되더라도 CS와 같은 야수의 보살을 중복 가산하지 않는다. 서로 다른 시도 그룹은 각각 집계한다.
- 중계에 `도루자 / 송구 포구 실책으로 세이프`를 표시한다.

### 2. 수비 병살·삼중살 참여

- 선택 정보 `multiOut`에 종류, 연속 수비 확인, 실제 아웃 행 ID, 판정 근거를 보존한다.
- 모달의 `수비 연속 아웃 기록`에서 DP/TP를 선택하고 관련 아웃을 확인한다.
- 실제 집계된 아웃 수와 선택 행이 일치해야 하며 각 아웃의 자살 야수가 필요하다. 취소된 외관상 아웃을 포함할 수 없다.
- 실책·폭투·포일·보크가 포함된 입력은 무실책·무미스플레이 연속 수비로 승인하지 않는다.
- 참여 자살·보살 야수의 집합에 DP 또는 TP를 한 번씩 기록한다. 같은 야수가 자살과 보살을 모두 했다고 DP가 두 번 증가하지 않는다.
- DP/TP와 GDP는 별개다. 삼진 후 도루자나 뜬공·어필 연속 아웃은 수비 DP/TP 대상이 될 수 있지만 자동으로 GDP가 되지 않는다.
- 선택하지 않은 기존 사건의 DP/TP는 소급 확정하지 않는다. 모달 미리보기에는 `미확정`으로 구분한다.

### 3. 미완성 병살타

- `groundedIntoDoublePlay`와 `incompleteDoublePlay`에 제2아웃 실패 행 및 판정 근거를 함께 보존한다.
- 모달에서 병살타를 선택한 뒤 `병살타 완성 여부`, `제2아웃 실패 행`, 보살 경로 및 근거를 지정한다.
- 첫 번째 실제 아웃은 포스 아웃 또는 타자주자의 1루 도달 전 아웃이어야 한다. 그 뒤에 두 번째 아웃용 송구의 포구 실책이 발생해야 한다.
- 역방향 병살 시도도 지원한다. 실책이 첫 아웃보다 먼저 발생하거나 두 번째 기회의 포구 실책이 아닌 입력은 거부한다.
- GDP 1, 실제 아웃 1, 해당 실책과 보살을 반영하되 수비 DP는 부여하지 않는다. 중계에도 미완성임을 명시한다.

### 4. 기존 기록 호환성

- 동결된 v1 코어는 수정하지 않았다. v2 어댑터에서 예외 입력을 변환하고 원래 구조화된 입력·주루 순서·근거를 복원한다.
- 신규 통계는 명시적으로 해당 예외를 입력했을 때만 부여한다. 기존 v2 사건에 DP/TP 필드를 일괄 추가하지 않는다.
- 기록 재정규화, 원본 비교, 기존 무결성 경고 흐름을 유지한다. 잘못된 사건을 정상 기록으로 우회 처리하지 않는다.

## 검증 중 발견하고 수정한 사항

1. 무실책만 확인하던 DP/TP 조건에 폭투·포일·보크 제외 조건을 추가했다.
2. 같은 도루 시도의 실책 세이프와 후속 아웃에서 CS·보살이 중복될 수 있어 이미 부여된 통계를 참조하도록 수정했다.
3. 통계 행이나 CS 값이 없는 주자의 초기화 누락과 미완성 GDP의 잘못된 타자 참조 경로를 수정했다. 해당 실패 조건을 단위 테스트에 고정했다.
4. 추가 단위 테스트의 괄호 누락을 수정했다. 각 사례를 Node 테스트 러너에 개별 등록해 테스트 수와 실패 위치를 명확하게 했다.

수정 후 타입 검사와 단위 테스트 780/780이 통과했다. 브라우저 결과와 산출물은 아래 최종 검증 결과에 별도로 기록한다.

## 남은 운영 과제

- 오류·미스플레이가 있는 긴 플레이 안에서 이후의 별도 무실책 구간만 DP/TP로 확정하는 세분화는 아직 지원하지 않는다. 이번 구현은 전체 복합 사건의 연속 수비 여부를 보수적으로 판단한다.
- 야수 교체·포지션 변경 시점에 따른 선수별 수비 통계 귀속과 공식 자료 대조가 필요하다.
- 과거 미확정 DP/TP를 자동 복원하거나 문자중계만으로 판정 근거를 자동 확정하지 않는다.
- 관리자 재심의 서버 영속 큐, 공식 기록과 잠정 기록의 비교 화면 연결 및 권한 경계의 통합 검증이 남아 있다.
- 실제 로그인, 저장·재조회, 운영 권한·배포 검증은 다음 별도 단계이며 이번 통과 결과로 대체하지 않는다.

따라서 이 보강과 테스트 통과는 KBO의 모든 예외 및 운영 준비 완료를 의미하지 않는다.

## 후속 진행: 선수별 수비 귀속

사건별 수비 위치 통계를 플레이 당시 선수에게 귀속하는 스냅샷과 읽기 전용 패널을 추가했다. 과거 자료를 현재 라인업으로 소급 추정하지 않으며, 식별 정보가 부족하면 위치별 기록을 보존하고 선수 귀속만 미확정으로 남긴다.

후속 검증은 단위 868건, 실제 브라우저 378건이 통과했다. 전역 선수 ID와 전체 수비 원장, 관리자 재심·공식 기록 비교 연결 및 운영 백엔드 검증은 여전히 남아 있다.
