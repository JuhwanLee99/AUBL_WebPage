# KBO 포스·타격방해·기록 재심 안내 보강

## 범위

이전 추가 점검에서 남긴 세 항목을 보강한다. 운영 DB에 접근하거나 로그인·배포를 진행하지 않는다. 이번 재심 목록은 클라이언트의 읽기 전용 진단이며, 서버에 저장되는 재심 업무 큐는 아니다.

## 규칙 근거와 구현

[KBO 2025 공식 야구규칙](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2025_%EC%95%BC%EA%B5%AC%EA%B7%9C%EC%B9%99.pdf)의 5.09(b)(6), 6.01(c), 9.12(a)(1)(F)를 대조했다. 최신 시즌 전체 규칙 검증은 여전히 별도 승인 조건이다.

| 항목 | 구현 내용 | 검증 사례 |
| --- | --- | --- |
| 포스 상태의 신체 태그 | 다음 베이스 도달 전 포스가 유지되면 일반 태그 선택 차단, 포스 선택 요구 | Q33~35 |
| 포스 재성립/해제 | 원래 베이스 귀루 후 재성립과 후위 주자 아웃 후 해제를 구분 | Q44~45, 기존 Q01~03/Q25 |
| 타격방해 출루 | 방해 벌칙 채택, 타석→1루 방해 원인, 방해 야수 실책 ID 및 행위 설명 필수 | Q36~40 |
| 만루 타격방해 | 여러 주자가 같은 실책 ID를 공유해도 수비·팀 실책은 1개 | Q41 |
| 실제 플레이 채택 | 타격 판정을 실제 결과로 기록하며 CI를 추가하지 않음 | Q42 |
| 방해 야수 책임 | 포수로 추측하지 않고 입력한 야수에게 실책 귀속 | Q43 |
| 과거 원본 오류 | 지원 버전, 파생값 일치, 신규 규칙 검증 실패를 진단 | 재심 픽스처 |
| 사건 채택 충돌 | 집계와 같은 원천 우선순위, 동일 우선순위 충돌은 재심 대상 | 재심 픽스처 |

타격방해는 기존 `steps[].errorId`로 연결한다. 방해 실책을 숫자만 자동 가산하지 않으므로 원본, 문자중계, 수비 증분, 팀 실책 집계가 같은 사건을 참조한다. 실책 종류는 현재 스키마의 포구/처리(`fielding`)를 사용하며 행위 설명을 반드시 기록한다. 기존 R19 픽스처의 실책 0 기대는 이 규칙에 맞춰 실책 1과 명시적 연결로 수정했다.

## 읽기 전용 재심 안내

- `scoringIntegrity.ts`가 현재 집계에 채택되는 사건을 기준으로 검증한다. 정상 수동 확정본이 낮은 우선순위의 잘못된 중계 재구성본을 대체하면 불필요한 경고를 남기지 않는다.
- 손상된 구조, 파생값 불일치, 미지원 버전, 수동 미확정, 동일 우선순위의 상충 원본을 목록에 표시한다. 같은 정상 원본의 단순 중복은 충돌로 보지 않는다.
- 기록원 화면과 실시간 관전 화면에 불완전 기록 경고를 표시한다. 기록원과 관전 화면 관리자만 사건 ID·사유·보존 원본을 펼쳐볼 수 있다. 일반 관전자는 상세 내용을 받는 UI 없이 공통 경고만 본다.
- UniquePlay 공식 상세의 기존 조기 반환/접근 게이트는 변경하지 않았다. 이 경고를 위해 공개 화면에서 비공개 아카이브를 추가 조회하지 않는다.
- 정상으로 표시하는 임의 닫기/무시 버튼을 제공하지 않는다. 실제 채택 원본이 정상으로 바뀌어야 경고가 해제된다.
- CSV 복합 사건 감사 행에 재심 사유를 덧붙이고 원본 JSON은 그대로 포함한다. 정상 사건의 기존 CSV 원본 행 형식은 유지한다.
- 원본 수정·삭제, 자동 점수 덮어쓰기, 재심 상태 서버 저장은 수행하지 않는다. 동일 우선순위 충돌의 자동 채택 정책을 이번에 바꾸지도 않는다. 경고가 있는 점수/통계는 확정치로 사용할 수 없다.

## 검증 구성과 경계

- 독립 규칙 시나리오를 32개에서 45개로 확장: 엔진 45회, 실제 모달 데스크톱/모바일 각 45회.
- 기존 모달 E2E 164개를 회귀 실행한다.
- 재심 모델 단위 테스트는 원본 비변경, 우선순위, 중복/충돌, 변조, 수동 미확정, CSV 원본 보존, 팀 실책 중복 방지를 검증한다.
- 재심 UI는 실제 컴포넌트·진단 모델에 격리 픽스처 8개를 주입하여 일반/관리자 × 데스크톱/모바일 32회를 실행한다. 실제 로그인·서버 권한 검사나 공식 소스 라우트 E2E를 의미하지 않는다.
- 모든 브라우저 하네스는 운영 모듈/외부 요청을 차단한다. 상태 교체 버튼은 테스트 전용이며 제품에 추가하지 않는다.

## 1차 검증

- 타입 검사 통과.
- 기존 및 확장 규칙 단위 테스트 680개 통과.
- 새 재심 단위 테스트 파일은 하네스 상대 경로 오류로 실행 전 실패했다(전체 프로세스 결과 680 통과, 파일 실패 1). 제품 규칙 실패로 분류하지 않는다.
- 새 하네스 두 파일의 경로 수정 승인 요청. E2E는 수정 후 실행한다.

## 아직 남는 운영 승인 조건

- 서버 영속 재심 큐, 과거 사건 수정 후 이후 플레이 전량 재구성·승인, UniquePlay 전환 후 비공개 비교 화면에 동일 재심 진단 연결.
- 실책으로 아웃을 면한 도루자, 미완성 병살타/방해 병살, 수비 DP/TP 및 선수별 PB 이력.
- 교체 시 BB/SO 책임, 자책점 재구성, 끝내기 타구와 경기 종료 규칙, 과거 플레이 어필.
- 검증 사례 통과는 위 미지원 범위를 포함한 운영 준비 완료 판정이 아니다. 로그인·실제 백엔드 저장/재조회 승인은 계속 보류한다.

## 후속 보강 연결

실책 세이프 도루자의 CS/E/A, 수비 DP/TP 참여, 미완성 GDP를 추가했다. 이전 무결성 UI 32건과 기존 E2E 164건을 재실행해 모두 통과했으며, 단위 테스트는 780건, 준비도 검증은 220건으로 확장됐다. 로그인·운영 백엔드 연동은 여전히 별도 승인·검증 단계다.
