# 사건 시점 기준 선수별 수비 기록 귀속

작성일: 2026-09-08

## 목적과 완료 범위

직전 단계에서 수비 위치별로 계산한 PO·A·E·PB·DP·TP를 해당 플레이 당시의 선수에게 귀속한다. 교체 후 현재 라인업으로 과거 기록을 다시 계산하는 방식은 사용하지 않는다.

기존 교체 처리의 문자중계만으로 과거 수비 배치를 복원하지 않고, 성공한 신규 모달 복합 사건에 수비 라인업 스냅샷을 보존한다. 선수별 집계는 원본 사건으로부터 재계산하는 읽기 전용 투영이다.

운영 로그인, 실제 서버 저장·재조회, 공식 기록 승격·배포는 이번 범위가 아니다. 전체 게이트는 `BLOCKED_BEFORE_LOGIN_BACKEND`를 유지한다.

## 설계 배경

1. 현재 선수 슬롯에는 전역 선수 ID가 없고 이름·등번호·포지션이 있다.
2. 기존 교체 함수는 라인업과 문자중계를 갱신한다. 이 정보만으로 모든 과거 플레이의 수비 선수를 확정할 수는 없다.
3. 따라서 현재 라인업이나 선수 이름만을 근거로 과거 수비 기록을 새 선수에게 넘기지 않는다.
4. 기록 시점에 확보한 정보가 부족하면 원래 위치별 통계를 보존하면서 선수별 귀속만 미확정으로 남긴다.

## 데이터와 처리 흐름

`PlayEvent.defensiveSnapshot`은 다음 정보를 보존한다.

| 필드 | 용도 |
| --- | --- |
| `version` | 수비 스냅샷 스키마 버전 1 |
| `matchId`, `playId` | 경기와 복합 사건 연결 |
| `inning`, `half`, `side` | 플레이 당시 이닝·공수·수비 팀 |
| `rosterKey` | 복합 사건 입력 컨텍스트의 라인업 버전 연결 |
| `lineup` | 수비 팀 선수의 이름·등번호·포지션 복사본 |

처리 순서는 다음과 같다.

1. 기존 실제 reducer가 `recordCompositePlay`를 처리한다.
2. 성공해 새 복합 사건이 생성된 경우에만 실행 전 상태의 수비 라인업을 복사한다.
3. 제3아웃으로 공수가 바뀌더라도 플레이 전 수비 팀에 기록을 귀속한다.
4. 저장 자료 정규화는 스냅샷을 보존한다. 누락된 과거 스냅샷을 현재 라인업으로 보충하지 않는다.
5. 조회 시 기존 원천 우선순위를 반영하고 복합 사건을 재정규화해 유효성을 확인한다.
6. 유효한 위치별 통계를 해당 스냅샷의 선수에게 귀속한다. 합계는 매번 사건에서 재계산하며 누적 값을 별도로 변경하지 않는다.

새 스냅샷은 현재 버전의 모달 복합 사건에만 추가한다. 단순 투구 입력마다 전체 라인업을 복제하거나 기존 이벤트 전체를 일괄 마이그레이션하지 않는다.

## 선수 식별과 미확정 처리

- 식별 키는 경기·팀·이름·등번호 조합이다. 전역 또는 시즌 선수 ID가 아니다.
- 같은 이름에 다른 등번호는 별도 선수로 구분한다.
- 포지션을 바꾼 동일 선수는 같은 키에 합산하며 참여 위치를 함께 남긴다.
- 이름 또는 등번호 누락, 같은 위치의 복수 선수, 같은 식별 정보가 여러 수비 위치에 있는 경우에는 관련 위치의 선수 귀속을 확정하지 않는다.
- DH는 실제 수비 위치로 간주하지 않는다. 같은 투수가 DH 슬롯에도 있는 경우 DH 복사본 때문에 수비 선수를 중복 처리하지 않는다.
- 사건·경기·공수·라인업 버전이 맞지 않거나 스냅샷 형식이 잘못되면 선수별 집계에서 제외한다.
- 불완전한 한 위치 때문에 근거가 명확한 다른 위치의 선수 기록까지 자동 폐기하지는 않는다.

유효한 위치별 통계에 대해서는 각 항목별로 `선수 귀속 합계 + 미귀속 합계 = 위치별 전체 합계`를 유지한다. 무효·충돌·수동 미확정 사건은 이 유효 합계에 포함하지 않고 별도 확인 사항으로 남긴다.

## 원천 우선순위와 중복

- 기존 집계와 같이 수동 기록, 실시간 기록, 문자중계 재구성 순으로 우선한다.
- 사건 ID가 같거나 복합 플레이 ID가 같은 중복 자료를 중복 가산하지 않는다.
- 동일 우선순위에서 원본 사건 또는 수비 스냅샷이 다르면 먼저 읽힌 자료를 임의로 선택하지 않는다.
- 우선순위 선택을 유효성 검사보다 먼저 한다. 상위 수동 기록이 미확정·무효라고 하위 실시간 복사본을 대신 확정하지 않는다.
- 재조회 과정에서 무효 복합 사건의 정상화가 실패해도 보존된 수비 스냅샷의 플레이 ID를 통해 관련 하위 복사본과의 연결을 유지한다.
- 스냅샷은 시점 근거이지 전자서명이나 서버 인증을 대체하는 자료가 아니다.

## 기록원 조회 패널

`선수별 수비 기록` 패널은 읽기 전용이다. 선수별 참여 위치와 PO·A·E·PB·DP·TP, 사건별 귀속 근거 및 미확정 사유를 제공한다. 공식 기록과 혼동하지 않도록 잠정·모달 복합 사건 범위를 표시한다.

기존 사건에 DP/TP 판정이 없으면 선수별 참여를 소급 확정하지 않는다. 둘 이상의 실제 아웃이 있으나 연속 수비 판정이 없는 사건은 DP/TP에 미확정 표시를 병기한다.

## 검증 설계

신규 단위 테스트는 88개다. 위치 코드·한글·숫자 별칭, 교체 전후, 포지션 교환, 초·말 수비 구분, 제3아웃, 스냅샷 참조 분리, 이름·등번호·포지션 충돌, 원천 우선순위, 중복, 저장 자료 정규화 및 합계 보존을 검증한다.

브라우저 수비 귀속 하네스는 실제 reducer와 실제 교체·포지션 변경 함수를 사용한다. 테스트 버튼이 구조화된 플레이를 입력하고 실제 수비 조회 컴포넌트를 검증한다. 이 하네스 자체가 모달의 모든 입력 칸을 클릭하는 검증은 아니다. 실제 모달 조작은 기존 모달 E2E 및 규칙 준비도 검증으로 별도 회귀 확인한다.

교체·포지션 변경은 실제 생산 함수를 추출해 테스트 상태에 적용한다. 교체 액션의 모든 권한 조건, 실제 로그인 및 백엔드 저장까지 검증했다는 의미는 아니다.

## 검증에서 발견한 사항과 보완

1. 다른 사건 ID로 들어온 같은 플레이의 상위 수동 기록이 무효·미확정인 경우, 하위 자료가 대신 합산되지 않도록 우선순위 결정 순서를 보완했다.
2. 초기 테스트 공통 입력에 판정 상태·어필 여부·실책 판정 근거가 빠져 있던 것을 보완했다.
3. 실제 추가 진루 없는 포일 테스트는 기존 엔진이 올바르게 거부했다. 테스트에 주자와 실제 포일 진루를 추가했다.
4. 실제 정규화 경로에서 신규 수비 스냅샷이 누락되는 문제를 수정했다. 정상·누락·잘못된 스냅샷의 재조회 회귀 테스트를 추가했다.
5. 상위 수동 기록의 무효·미확정 상태가 재조회 후에도 유지되는 대조 테스트를 추가했다.

타입 검사와 전체 단위 테스트 868/868이 통과했다. 최종 브라우저 검증 결과와 실행 증거는 아래에 별도로 기록한다.

## 남은 과제와 비보장 범위

- 전역 선수 ID를 도입하지 않았다. 동일 팀에서 같은 이름·등번호를 서로 다른 사람이 사용하는 경우와 경기 중 이름·등번호 정정은 별도 신원 확인이 필요하다.
- 과거 스냅샷이 없는 사건과 비모달 기록의 선수 귀속은 자동 복원하지 않는다.
- 수비 이닝·수비 기회·수비율·시즌 합산·공식 선수 원장을 완성한 것은 아니다.
- 한 플레이 도중의 수비 역할 변경이나 실책 이후 별도 연속 수비 구간의 DP/TP 확정은 추가 설계 대상이다.
- 스냅샷 수동 정정과 관리자 재심 영속 큐, 유니크플레이 공식 자료와의 비교 워크플로우 연결이 남아 있다.
- 실제 서버 저장·재조회, 이벤트 전송 크기·보존 정책, 로그인·권한 및 운영 배포는 별도 검증 단계다.

이번 변경은 사건 시점의 수비 귀속 기반을 마련한 것이며, 전체 야구 기록 및 운영 준비 완료를 의미하지 않는다.

### 하네스 잔여 사항

최초 신규 하네스 실행에서 Vite가 프로젝트의 다른 HTML 진입점까지 의존성을 탐색해 테스트 스토어에 없는 운영 Provider 내보내기 오류 로그를 남겼다. 실제 운영 Provider가 실행되거나 운영 요청이 발생한 것은 아니다. 최종 재실행에서는 해당 로딩 오류가 재현되지 않았으며 36건이 모두 통과했다.

테스트 진입점으로 탐색을 제한하고 캐시를 분리하는 변경은 제안했으나 아직 승인을 받지 않아 적용하지 않았다. 새 환경 또는 캐시 초기화 시의 하네스 재현성 개선 과제로 남긴다.

## 후속 완료: E2E 캐시 격리와 관리자 재심 연결

이전 단계의 미완료 항목인 수비 E2E 하네스 탐색 범위·캐시 분리를 완료했다. 실행별 Vite 캐시, 지정 진입점과 React 의존성, 자동 탐색·감시·HMR 비활성화 상태에서 36/36 통과했다. 당시 실패·대기 이력은 수정하지 않고 남긴다.

보관 수비 귀속 문제를 관리자 이슈 초안으로 전달하는 흐름도 추가했다. 물리 문서 ID, 포지션, 경기·공식 리비전·해시, 부분 조회 범위를 근거에 보존하고 원본 스냅샷은 수정하지 않는다. 관리자 E2E는 승인된 선택자 수정 후 34/34 통과했다. 전체 경기·시즌 수비 기록의 완전성 인증은 아니다.
