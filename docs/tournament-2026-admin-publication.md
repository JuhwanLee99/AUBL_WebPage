# 2026 토너먼트 대진 · 홈 전환

## 적용 범위

- 사용자 제공 예상 대진 이미지 두 장의 자리와 연결 순서를 기본 초안으로 반영한다.
- 관리자: `/admin/tournament`. 방문자: `/tournament` 및 홈 조 현황 영역의 토글.
- 신규 Firestore 문서는 관리자 저장 전까지 생성하지 않는다. 기본 상태는 비공개이며 홈은 기존 조별예선이다.
- 로컬 타입 검사·빌드·규칙 에뮬레이터·브라우저 검증 결과는 아래 실행 기록을 따른다. 운영 배포와 운영 DB 쓰기는 실행하지 않았다.

## 이미지 대조용 기본 대진

각 행의 두 팀이 16강에서 맞붙는다. 같은 쪽의 1·2경기, 3·4경기 승자가 각각 8강에서 만나고, 그 승자들이 준결승에서 만난다. 양쪽 준결승 승자가 중앙 결승에서 만난다.

| 구분 | 왼쪽 위에서 아래 | 오른쪽 위에서 아래 |
|---|---|---|
| 으뜸 1 | D2 / G1 | G2 / E1 |
| 으뜸 2 | H2 / F1 | A2 / C1 |
| 으뜸 3 | E2 / H1 | C2 / D1 |
| 으뜸 4 | F2 / B1 | B2 / A1 |
| 버금 1 | D4 / B3 | F4 / A3 |
| 버금 2 | E4 / H3 | A4 / E3 |
| 버금 3 | C4 / D3 | B4 / C3 |
| 버금 4 | G4 / F3 | H4 / G3 |

이미지의 보라색 선택 테두리, 페이지 번호, 편집자 배지는 경기 정보가 아니므로 제외했다. 현재 순위와 최종 진출 확정을 혼동하지 않도록 팀명을 실시간 순위에서 자동 배정하지 않는다.

## 관리자 작업 순서

1. 토너먼트 관리에서 기본 초안을 확인한다.
2. 진출 자리 선택을 변경하면 기존 자리와 교환된다. 각 구간의 16개 자리는 중복 없이 유지된다.
3. 실제 진출이 확정되면 팀명을 입력한다. 두 구간에 같은 이름을 중복 배정할 수 없다. 점수 입력 이후 팀명은 잠긴다.
4. 16강부터 결승까지 일시(KST), 장소, 경기 상태, 점수를 입력한다. 미정 일정은 빈칸으로 유지한다.
5. 비공개 초안 저장을 눌러 작업을 보관한다. 공개본에는 영향을 주지 않는다.
6. 미리보기 검토 후 현재 내용 공개·갱신을 누른다. 입력과 공개본을 한 트랜잭션으로 반영한다.
7. 토너먼트 시작 단계로 바꾸면 홈 기본 화면이 토너먼트로 선택된다. 공개·갱신해야 적용된다. 조별예선 토글은 계속 제공한다.
8. 공개 해제는 공개 데이터에서 대진 내용을 제거하고 홈을 조별예선으로 돌린다. 초안은 보존한다.

브라우저의 진행 중 선택은 유지하며 새 방문자는 게시된 홈 기본 화면을 사용한다. 같은 페이지에서 조별 화면을 숨길 때에는 컴포넌트를 유지하여 선택한 조를 보존한다.

## 저장·공개 경계

- `tournamentDrafts/season2026`: 관리자 claim이 있는 계정만 읽기·생성·수정 가능.
- `tournamentPublic/season2026`: 공개본 하나만 익명 단건 조회 가능. 목록 조회는 금지.
- 비공개 공개 문서에는 revision, enabled=false, updatedAt만 남긴다. 비공개 초안을 공개 config 컬렉션에 넣지 않는다.
- 공개 시 public.config가 트랜잭션 이후 draft.config와 같은지 Firestore 규칙으로 확인한다.
- 초안·공개본은 각자의 증가 revision을 가진다. 다른 관리자가 변경한 경우 자동 덮어쓰지 않고 최신 자료 재조회 안내를 표시한다.
- 오프라인 트랜잭션 실패 시 성공으로 표시하지 않는다. 입력은 화면에 유지된다. IndexedDB 영속 편집 큐는 이번 범위가 아니다.
- 방문자는 서버 확인을 받기 전 로컬 캐시의 대진을 표시하지 않는다. 서버 연결 실패 시 공개 내용을 숨긴다.
- 이미 방문자가 읽거나 캡처한 이전 공개본을 공개 해제로 회수할 수는 없다.

## 결과와 정정

- 16강 참가 자리는 고정 대진에서, 후속 라운드는 앞 경기의 종료 승자에서 결정한다.
- 종료에는 양쪽 참가 자리와 서로 다른 두 정수 점수가 필요하며 높은 점수의 참가자가 승자다.
- 승자를 변경하면 참가자가 달라지는 모든 후속 경기의 점수·승자를 초기화한다. 일정·장소는 유지한다.
- 결과가 있는 상태에서 16강 대진을 교환하면 확인 후 해당 구간 전체 결과를 초기화한다.
- 이 화면의 결과는 대진 운영용이다. UniquePlay 공식 원천, 시즌 누적, 기존 경기 일정·기록을 자동 수정하지 않는다.
- 몰수 사유, 재경기, 경기별 기록 ID 자동 연결과 공식 결과 자동 동기화는 아직 포함하지 않는다. 몰수의 공식 판정이나 누적 기록을 이 화면에서 산출하지 않는다.

## 배포 전 검증 목록 (실행 여부는 아래 결과 참조)

- 이미지 32자리와 모든 8강·준결승·결승 연결이 일치하는지 대조.
- 익명·일반 회원의 초안 읽기/쓰기 거부, 관리자의 초안 저장/공개/해제 허용.
- 공개본이 없는 상태, 저장 초안만 있는 상태, 초안 수정 중에도 기존 공개본 유지.
- Firestore 규칙의 공개본-초안 일치 조건, revision 경쟁, 공개 해제 시 config 제거 확인.
- 수정 충돌, 권한 만료, 오프라인 저장 실패 시 입력 유지 및 성공 안내 미표시.
- 선행 승자 정정 후 연쇄 결과 초기화, 일정 유지, 중복 자리·동점 종료·미정 참가자 점수 거부.
- 토너먼트 시작/종료/예상 단계, 홈 기본 토글, 조별 화면 선택 보존, 비공개 복귀.
- PC·모바일에서 좌우 스크롤, 긴 팀명, 일정 표, 키보드 포커스, 관리 화면 입력.
- 타입 검사와 실제 앱 라우트 검사 후 Firestore 규칙 및 프런트엔드를 함께 배포해야 한다.

배포만으로 공개되지 않는다. 운영진이 관리자 페이지에서 초안을 저장하고 공개해야 방문자에게 노출된다.

### 확인한 내용

- 이미지의 32개 진출 자리와 양쪽 결승 진출 경로, 후속 라운드 참가자 확정.
- 선행 승자 정정 시 영향받는 후속 경기만 초기화하고 일정·장소 및 반대편 결과 보존.
- 같은 승자의 점수 정정은 후속 결과 보존. 자리 교환은 중복 없이 반영하고 결과 초기화.
- 익명·일반 회원의 초안 읽기와 쓰기, 공개본 쓰기 및 목록 읽기 거부.
- 초안 저장은 공개본을 바꾸지 않음. 공개 트랜잭션의 원본 일치와 revision 충돌 거부.

- Chromium 390px/1440px에서 공개·관리자·홈 페이지의 전체 가로 넘침 없음. 대진과 일정 표는 내부 가로 스크롤 사용. 버튼 각진 테두리 확인.

### 날짜 검증 결함 수정 완료

최초 실행에서 `validateTournament`가 `2026-02-30T12:00:00+09:00`을 허용하는 결함을 확인했다. `Date.parse`가 존재하지 않는 일자를 다음 달로 정규화하기 때문에 유한한 timestamp 여부만으로는 달력 유효성을 판단할 수 없었다.

사용자 승인 후 `isValidSchedule`에서 파싱된 시각을 KST 달력 문자열로 되돌려 입력 연·월·일·시간·초와 정확히 일치하는지 확인하도록 수정했다. 기존 실패 테스트를 유지하고 경계 테스트 19건을 추가했다. 평년 2월 29일, 4·6월 31일, 월·일 범위 초과, 24시, 60분, 다른 시즌의 윤일은 거부하며 2026년의 실제 말일·연말·자정·미정 일정은 허용한다. 이 기능은 2026 시즌 전용이다.

수정 후 타입 검사, 단위 79건, Firestore 21건, 브라우저 10건, 프로덕션 빌드까지 재실행해 모두 통과했다. 운영 배포는 실행하지 않았다.

### 테스트 하네스 수정 이력

첫 브라우저 실행은 4/10 통과했다. 드롭다운 라벨 완전 일치 선택자가 옵션 텍스트까지 포함하는 이름을 찾지 못해 후속 공개 시나리오가 연쇄 실패했다. 승인 후 드롭다운을 역할 기반으로 바꾸었고, 안내 문구 textarea에도 같은 원인이 있어 역할 기반 선택자로 변경했다. 최종 재실행은 10/10 통과했다. 이 과정에서 제품 코드는 변경하지 않았다.

### 격리·재현

전용 `demo-aubl-tournament` 프로젝트, `127.0.0.1:8789` Firestore, `127.0.0.1:5197` 브라우저 하네스만 사용했다. 브라우저의 다른 호스트 요청은 차단했다. 에뮬레이터는 실행 종료 시 정상 종료했으며 운영 데이터는 생성하거나 변경하지 않았다.

```sh
node --experimental-strip-types --test scripts/test-tournament-model.mjs
firebase emulators:exec --config firebase.tournament-test.json --only firestore --project demo-aubl-tournament 'node --experimental-strip-types scripts/test-tournament-firestore.mjs'
firebase emulators:exec --config firebase.tournament-test.json --only firestore --project demo-aubl-tournament 'node scripts/test-tournament-ui.mjs'
```

브라우저 캡처는 `.tmp/tournament-tests/{public,admin,home}-{390,1440}.png`에 있다. 테스트는 Firebase 클라이언트만 에뮬레이터로 주입하는 MemoryRouter 하네스다. 실제 로그인·RequireAdmin을 포함한 전체 앱 라우트, 권한 회수, 오프라인 복구, 실제 모바일 기기, 운영 배포는 검증하지 않았다. 오래된 revision 거부는 확인했으나 두 관리자 동시 클릭의 경합 자동화는 별도 과제다.
