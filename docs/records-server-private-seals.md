# 비공개 최종 저장 체크포인트 봉인

작성일: 2026-09-08

## 구현

`functions/scoring_test_seals.py`에 내부 봉인 서비스를 추가했다. `SCORING_TEST_SEAL_ENABLED` 기본값은 비활성이며 실제 활성화·외부 API·배포는 수행하지 않았다.

봉인은 실행 인가·승인 해시, 현재 작성자·세션·epoch, 최종 revision·commit ID·payload hash·마지막 입력 순번을 대조한다. 클라이언트의 큐가 비었다는 주장이나 시간 경과만으로 허용하지 않는다.

최종 요청 ID로 서버 커밋 영수증을 찾아 같은 내용을 검증하고 manifest·블록의 무결성도 다시 검사한다. 성공 시 봉인 영수증 생성, head의 sealed 표시, 작성 세션의 sealed 상태를 하나의 트랜잭션으로 반영한다. head는 계속 private 상태다.

동일 봉인 요청·동일 내용은 기존 봉인 결과를 반환한다. 다른 내용으로 같은 ID를 재사용하거나 head·세션의 봉인 상태가 서로 다르면 거부한다. 자동 봉인 해제·재개·인계는 제공하지 않는다.

## 늦은 쓰기와 경합

업로드와 커밋은 최종 저장 트랜잭션에서 작성 세션을 읽는다. 봉인이 먼저 확정되면 active 세션 검사가 실패한다. 커밋이 먼저 확정되어 head가 바뀌면 이전 revision을 대상으로 한 봉인은 거부된다. 커밋에는 sealed head의 신규 쓰기 거부 조건도 추가했다.

세션 획득과 인계도 sealed 세션을 active 세션으로 덮어쓰지 않는다. 봉인 후에도 비공개 동일 revision 조회는 허용하되 기존 참여자·실행 인가를 유지한다. 과거 커밋 ACK 재조회는 현재 세션 인가에서 거부될 수 있으며 봉인 요청 자체는 별도 멱등 경로로 재조회한다.

업로드가 먼저 끝났으나 커밋되지 않은 준비 블록이 남을 수 있다. 봉인은 이런 블록을 임의 삭제하지 않으며 후속 고아 정리 정책이 필요하다.

## 의미와 제한

`sealKind: storage-checkpoint`는 저장 체크포인트의 봉인을 뜻한다. 야구 경기의 적법한 종료, 미해결 판정 없음, 모든 로컬 기기의 큐가 비었음, KBO 규칙 적합성을 인증하지 않는다.

경기 종료 사건·의미 검증, 마지막 로컬 ACK 확인, 인계 잔여 큐 검토를 실제 서비스에서 연결한 뒤에만 공식 전환의 전제 조건으로 사용할 수 있다. 현재 UniquePlay 전환의 기존 15초 조건이나 NAS 경로는 변경하지 않았다.

## 검증 상태

최초 구현 이후 아래 정상 봉인·동일 요청 복구, 잘못된 영수증·해시·revision, 누락·변조 블록, 봉인 후 업로드·커밋·인계 거부, 봉인과 최종 커밋 경합, 봉인 RPC 응답 유실 검증을 실행했다.

전체 상태는 `BLOCKED_BEFORE_LOGIN_BACKEND`이며 관전자 공개·운영 활성화는 차단 상태를 유지한다.
