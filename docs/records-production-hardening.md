# 모달 야구기록 운영 준비도와 보완 작업

작성일: 2026-09-08. 이번 작업은 제품 코드 보완이며, 운영 배포나 운영 데이터 수정이 아니다.

## 1. 결론과 검증 경계

복합 플레이 입력은 희귀한 단일 플레이의 연속 주루와 복수 실책 등을 표현한다. 그러나 **모든 야구 상황을 자동 판정하거나 운영 저장의 정합성을 보장하는 단계는 아니다.** 입력 가능, 규칙 검증, 통계 보존, 서버 확정은 각각 별도 승인 조건이다.

직전 기준선은 코어 테스트 269건, 격리 프런트엔드 E2E 30건 통과다. 이번 수정 이후 테스트, 타입 검사, 브라우저 재검증은 실행하지 않았다. 기존 통과 결과를 이번 변경의 검증 결과로 인용하지 않는다. 실제 Firebase 저장·재조회 검증도 미실시다.

## 2. 발견한 부족한 부분과 이번 수정

| 우선순위 | 문제와 영향 | 이번 구현 | 현재 판정 |
|---|---|---|---|
| P0 | 실행 취소/재실행이 일반 잠금 검사보다 앞서 실행됨 | 복합 입력과 이력 조작에 현재 기록원 소유권·일시정지 검사 추가. 다른 경기 이력 복원 차단, 현재 잠금 정보 유지 | 구현, 재검증 필요. 서버 권한 검사를 대신하지 않음 |

| P1 | 종료 타자 기록의 타입·정규화·집계·관전자 변환에서 CI/SH/SF/SB/CS/GDP 일부 누락 | 빠진 필드의 전달 경로 확장, 미확정 SH/SF는 임의의 0으로 보완하지 않음 | 구현. 과거에 이미 유실된 데이터 자동 복구는 아님 |
| P1 | 관전자 종료 투수 변환에서 WP/BK/SH/SF 누락 | 실제 존재하는 값을 전달 | 구현. 기존 미수집 기록의 완전성 보증은 아님 |
| P1 | 출루율에 타격방해가 포함되고 희생번트를 희생플라이처럼 처리 | 공유 계산 함수로 표와 양쪽 CSV 계산 통일, 합계와 SH+SF가 불일치하면 미확정 표시 | 구현, 독립 기대값 재검증 필요 |
| P1 | 희생 합계 열을 희생플라이라고 표시 | 합계·SH·SF 구분, SB/CS/GDP 및 출루율 상태 열과 CSV 항목 추가 | 구현, 모바일 가로 스크롤 재검증 필요 |
| P2 | 관전자 중계에 내부 실책 UUID와 영문 유형 표시 | 공개 표시 전용 함수로 야수·실책 종류·플레이 내 참조 번호 표시 | 구현. 이미 저장된 과거 중계 문장은 마이그레이션하지 않음 |

출루율 계산 근거는 [KBO 공식 야구규칙 9.21(f)](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2025_%EC%95%BC%EA%B5%AC%EA%B7%9C%EC%B9%99.pdf#page=190)다. 계산은 `(H + BB + HBP) / (AB + BB + HBP + SF)`이며 희생번트와 방해에 의한 출루는 포함하지 않는다. `sac`만 남아 있는 과거 기록은 희생플라이 개수를 추측하지 않는다. 복합 사건의 일부 SH/SF만 있는 혼합 기록도 합계가 맞지 않으면 출루율을 확정 표시하지 않는다.

기존 `CompositeRecord.version=1`의 원본 `feed`, 실책 ID, 검증용 파생값은 변경하지 않았다. 공개 중계 문구만 별도 함수에서 변환해 기존 원본의 재계산 비교 계약을 유지한다. 미사용 함수 제거·추가 주석 전환도 하지 않았다. 기존 주석 보존은 유지한다.

## 5. 권장 진행 순서와 운영 안전

1. 이번 변경의 타입 검사, 관련 단위 테스트, 기존 격리 E2E와 H01~H15를 검증한다. 실패를 제품 결함과 하네스 결함으로 구분한다.
2. PROD-01~03을 별도 서버 저장 계약으로 구현하고, 에뮬레이터에서 같은 길이 정정·부분 실패·응답 유실·동시 작성·권한 회수를 검증한다.
3. RULE/STAT 항목을 규칙 카탈로그와 독립 기대값에 연결한다. [2026 KBO 변경 규정](https://www.koreabaseball.com/Kbo/League/GameManage2026.aspx)과 대상 대회 규정을 대조하되, 2026 전체 규칙집 대조 완료로 표현하지 않는다.
4. 구형 경로와 실제 페이지를 검증한 뒤 기능 플래그와 제한된 기록원으로 시범 운영한다. 확정되지 않은 기록은 관전자 확정 통계와 구분한다.

운영 데이터 쓰기는 이번 작업에서 하지 않았다. 향후 실제 저장 검증이 필요하면 먼저 운영 분리 환경을 사용한다. 불가피한 운영 검증은 테스트 경기 표시·전용 ID·생성 범위 추적·정리 계획이 갖춰진 뒤 별도 승인으로 진행한다. 기존 실제 경기 기록을 검증용으로 수정하거나 삭제하지 않는다.

## 후속: 원자적 저장 계약 및 테스트 확대

[신규 저장 계약과 검증 확대 계획](./records-atomic-storage-test-expansion.md), [실제 실행 결과와 미해결 실패](./records-atomic-validation-2026-09-08.md)를 추가했다. 신규 Firestore 어댑터·규칙·outbox는 격리 경로에서 구현했으며, 기존 운영 Provider/관전자 경로의 전환은 아직 진행하지 않았다. 코어 및 신규 단위 테스트 565건, 브라우저 E2E 164회, Firestore SDK/규칙 24건을 실행했다. 실패를 제외하거나 기존 통과 결과로 대체하지 않았으며 제품/하네스 수정 후 재검증이 필요하다.

## 후속: 승인된 오류 수정 재검증

[최신 재검증 결과](./records-atomic-revalidation-2026-09-08.md)를 추가했다. 동일 사건 재전송의 불필요한 이력 생성과 기존 하네스 오류를 수정했으며, 신규 HTTP/1 프록시의 gRPC 비호환 문제는 별도 미해결 항목으로 남겼다. 운영 저장 경로는 아직 전환하지 않았다.

## 2026-09-08: 실시간 참고 기록 / UniquePlay 공식 기록 분리

공식성의 기준을 자체 모달 기록이 아닌 검수·게시된 UniquePlay 리비전으로 분리하는 기반을 추가했다. 상세 정책, 서버 전환, 관리자 보관·비교, NAS 연계 조건, 배포 순서 및 미실행 검증 계획은 `docs/records-source-lifecycle.md`에 정리했다.

- 새 공식 전환 함수와 자동 트리거는 기본 비활성 상태이며 운영 데이터에 적용하지 않았다.
- 자체 기록의 MariaDB 공식 임포트 경로는 코드에서 중단하고 기존 로직은 주석으로 보존했다. 실제 운영 동작은 별도 배포 전까지 변경되지 않는다.
- 이전 기록 엔진·Atomic 프로토타입의 테스트 결과는 이번 원천 전환 기능의 검증 결과가 아니다. 이번 변경은 타입·권한·E2E 검증 전 상태다.
- 다음 운영 승인 조건은 NAS 공식 통계 원천·프로젝션 계약 확인, 마지막 자체 기록의 서버 ACK 확인, 공식 전환 후 비관리자 원본 접근 거부 검증이다.

### 출처 전환 격리 검증 후속 결과

`docs/records-source-validation-2026-09-08.md`에 실행 결과와 실패·수정 이력을 추가했다. 신규 권한 83건, 서버 정책·트랜잭션 12건, 신규 출처·비교 단위 37건, 신규 E2E 16건 및 기존 회귀 검증이 최종 통과했다. 기존 장애 주입 하네스 2건은 제외했고 운영 DB 및 자동 전환 설정은 변경하지 않았다. 실제 NAS 연계와 전체 공유 Store Provider 경합 검증은 후속 승인 조건으로 유지한다.

## 후속: 로그인·백엔드 연동 전 최종 판정

[최종 점검 문서](/Users/juhwan/Documents/Dev/AUBL/main/docs/records-preintegration-final-check-2026-09-08.md)에 최신 구현과 과거 미완료 항목을 대조했다. 관리자 재심·수비 귀속의 후속 검증은 완료됐지만 실제 Provider의 원자적 저장 전환과 서버 ACK 경계는 미완료다. 저장 대기 중 다음 입력을 완료 길이에 포함하는 정적 위험, Firestore 외 인증·Functions 격리 공백, 공식 전환의 마지막 커밋 확인 부재도 진입 차단 항목으로 정리했다.

실행한 회귀는 통과했으나 실제 RPC 장애 주입 2건을 제외했고, 운영 로그인·백엔드 진입은 승인하지 않았다. 실제 브라우저 실행 440회와 공식 화면 Node 테스트 15건을 구분한다. 운영 자료와 제품 코드는 변경하지 않았다.
