# 기록 시스템 검수 및 재해석 엔진 구현 현황

기준일: 2026-09-08. 이 문서는 이전 진행 메모를 대체하며, 실제 구현 범위와 미완료 사항을 구분한다.

후속 단계로 [구조화 주루 매트릭스](records-runner-matrix.md)를 추가했다. 아래 검수 내용은 재해석 기반 구축 당시의 범위이며, 실제 주루 입력·저장·제3아웃 득점 처리의 확장 범위는 후속 문서를 기준으로 한다.

그 다음 단계의 [안타 입력·책임 실점 연결](records-hit-integration.md)에서는 기존 안타/홈런 액션을 구조화 전이로 전환하고 기록원·점수관 집계에 저장된 주자 책임을 연결했다.

## 검수 결론

최근 작업은 공통 문자중계 파서, 후보 선택 UI, 메타데이터, 실시간 입력 검증 진입점을 추가했다. 하지만 정상 후보의 일괄 수동확인 처리, 미확정 후보 반영, 원본 기록 덮어쓰기, 과거 이벤트에 메타데이터 부착 등의 회귀가 있었다. 이번 단계에서는 이 경로를 수정하고 구조화 상태를 재생하는 감사 모듈을 연결했다.

현재 구현은 KBO 모든 사건에 대한 완성된 규칙 엔진이 아니다. 실시간 입력은 기존 전이 함수를 유지하며, 새 상태 재생은 별도의 검수 경로로 동작한다. 이 구분은 화면에도 안내한다.

## 검수에서 발견하고 수정한 문제

| P1 | 이벤트는 앞에 추가되는데 메타데이터는 뒤의 과거 이벤트에 부착 | 객체 동일성으로 새 이벤트만 식별하고 상태 전이 부착 |
| P1 | 낮은 신뢰도/다중 후보도 기본 선택값으로 상세 기록·CSV 반영 | 명시적으로 확정하지 않은 검토 대상은 선택 결과에서 제외 |

## 구현한 데이터와 처리 흐름

### 실시간 입력

`기존 액션 → applyScoringEvent → 기존 전이 함수 → 상태 형태 검증 → 새 사건 메타데이터/전이 저장`

- `PlayEvent.stateTransition`: 버전 1, 입력 전후의 이닝·초말·아웃·베이스 점유·팀 점수.
- `PlayEvent.rebuildOrigin`: 원천 사건 ID, 조각 번호, 전체 조각 수.
- 한 액션이 여러 이벤트를 생성하면 전체 전이를 각 이벤트에 중복 부착하지 않는다. 이 경우 개별 전이가 없으므로 상태 재생에서는 보류된다.
- 실패한 입력은 경기 상태/정상 이벤트를 유지하고 `DemoSnapshot.scoringRejections`에 시각·경기 ID·유형·사유를 남긴다. 기존 history를 통한 되돌리기가 가능하다.
- 이 반려 내역은 경기 스냅샷에 포함된다. 불변의 서버 감사 원장이나 입력 액션 전체를 저장하는 체계는 아니다.
- 전이와 원천 ID는 `normalizeEvents`에서 유지한다. 손상된 전이는 버리고 수동확인 사유를 남긴다.
- feature flag `aubl-scoring-engine-v1`의 기존 동작을 유지한다. `0/false/off/disabled`로 입력 검증을 끌 수 있으며 기본은 활성이다. 저장소 접근 예외로 기록 화면이 중단되지 않게 처리했다.

### 문자중계 재해석

`중계 원천 → 후보/근거 생성 → 자동 또는 명시적 확정 → 원본과 병합 → 화면/CSV`

- `rebuildEventsFromFeedWithAlternatives().events`는 검토용 전체 후보 목록이다.
- 실제 반영에는 반드시 `selectRebuildEvents()`를 사용한다. 호환 함수 `rebuildEventsFromFeed()`도 이 필터를 거친다.
- 미분류 문장은 낮은 신뢰도로 남기고 보류한다. 중간 볼/스트라이크/파울은 인식하되 최종 플레이 이벤트에 넣지 않는다.
- 단일 후보도 보류 사유가 있으면 확정이 필요하다. 후보를 바꾸는 행위와 확정 버튼을 구분한다.
- 확정은 `manual` 출처와 정정 사유를 남긴다. 공식 기록 보정 권한을 뜻하지 않는다.
- 복합 사건은 모든 조각을 확정해야 병합한다. 일부 조각의 확정만으로 기존 한 사건을 부분 대체하지 않는다.
- 분류가 변경된 후보에 기존 사건의 상태 전이를 물려주지 않는다. 이전 전이를 새 판정의 검증 근거로 사용할 수 없기 때문이다.
- 원본 이벤트 및 원본 중계는 수정하지 않는다. 같은 입력을 반복 병합해도 같은 결과가 나오도록 회귀 테스트를 추가했다.

### 상태 재생과 감사

`src/shared/lib/scoringReplay.ts`는 저장소와 UI에 의존하지 않는 상태 재생 모듈이다.

- 구조화된 전이를 사건 순서대로 적용하고, 전후 상태의 정합성 및 연속성을 검사한다.
- 아웃/점수 값, 주자 중복, 공수 순서, 교대 후 초기화, 같은 공수에서의 아웃 감소, 비공격 팀 점수 변경을 검사한다.
- 득점 감소/수비 팀 점수 변경의 예외는 명시적인 수동 공식 보정일 때만 허용한다.
- 동일 ID의 같은 전이는 재적용하지 않고, 내용이 다른 전이는 충돌로 반려한다.
- 반려 시 직전 상태를 보존한다. 과거 상태로의 재생은 사건 목록의 원하는 접두 구간을 다시 적용하는 방식으로 가능하다.
- 전이 정보가 없는 기존 사건은 `pending`이다. 다음 구조화 사건은 별도 구간으로 시작할 수 있지만 전체 경기 검증 완료로 표시하지 않는다.
- 판정 자체의 옳고 그름, 실제 제3아웃 발생 여부, 득점 주자의 신원 및 득점 허용 시점을 이 스냅샷만으로 증명하지 않는다.

### 화면 및 CSV

- 점수관 경기 종료 재해석 패널: 기존 기록/후보/사유, 후보 확정, 재해석 제외, 확정 되돌리기.
- 기존 관리자 권한에 따라 확정 조작을 제한한다. 이 단계에서는 로컬 미리보기이며 서버 쓰기를 수행하지 않는다.
- 경기 ID 또는 중계 내용이 변경되면 이전 확정값이 새 데이터에 적용되지 않는다.
- 상태 적용/검증 보류/반려 건수와 반려 사유를 표시한다.
- 점수관/기록원 CSV에 `문자중계 재해석 감사`, `상태 재생 감사` 섹션을 추가했다.
- 미확정 재해석은 상세 플레이에서 제외되지만 감사 섹션에 보류로 남는다. 기존 직접 입력 사건은 유지한다.
- 확정 선택은 현재 화면 세션에만 존재한다. 새로고침 후 유지, 다른 기기와 공유, 점수관 선택을 기록원 CSV로 전달하는 저장 기능은 아직 없다.
- CSV의 후보 확정 상태와 최종 원본 우선 병합 결과는 서로 다른 항목이다. 후보 확정만으로 점수판/선수 집계를 수정했다고 해석하면 안 된다.

## 검증

재현 명령:

```sh
npm run test:scoring
npm run typecheck
./node_modules/.bin/eslint src/shared/lib/scoringReplay.ts src/shared/lib/playFeedParser.ts
```

- `test:scoring`: 기반 37개, 주루 매트릭스 26개, 안타/책임 연결 25개로 합계 88개 통과.
- `typecheck`: 전체 애플리케이션 타입 검사 통과.
- `eslint`: 파서와 상태 재생 모듈 검사 통과.
- 위 테스트 안에 공백/줄바꿈을 변형한 합성 중계 500건, 결정적 난수 기반 상태 전이 200건이 포함된다.
- 합성 중계는 볼넷·사구·번트안타·2루타·폭투의 5개 패턴을 변형한 것이다. 실전 중계 500건 검증을 완료했다는 의미가 아니다.
- 초기 실행에서 기존 정규식 오류와 출처 객체 타입 오류를 발견해 수정했다.
- 실제 브라우저 조작, Firestore 저장/복구 통합 시험, 운영 경기 회귀 비교, 프로덕션 빌드·배포는 이번 검증 범위에 포함하지 않았다.

## 규칙 근거와 남은 구현 순서

공식 규칙 참조 문서는 [KBO·KBSA 2025 공식야구규칙](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2025_%EC%95%BC%EA%B5%AC%EA%B7%9C%EC%B9%99.pdf)이다. 이번 검수에서는 문서의 발행 주체와 판본을 확인했다. 최신 판본 전체 대조와 세부 규칙별 승인 시험은 완료하지 않았다.

1. 구조화된 주루 매트릭스: 주자 ID·출발/도착 루·아웃 종류·발생 순서·책임 투수를 명시적으로 입력. 조각별 주자 이동 연결도 이 단계에서 해소한다.
2. 규칙별 전이: 제3아웃과 득점 인정, 포스/태그/어필, 낫아웃, 방해·보크, WP/PB, 병살/삼중살을 명시적 사건과 연결한다. 문자열 단어만으로 해당 판단을 확정하지 않는다.
3. 보정 영구 저장: 경기 버전/작성자/사유/변경 전후/롤백 관계를 보존하고, 동일 버전에 대한 충돌 검사를 서버에서 처리한다.
4. 공통 재집계: 확정 사건 원장에서 점수판·타자·투수·책임 실점/자책점을 함께 재계산한다. 현재는 기존 집계 경로가 유지된다.
5. 회귀 자료와 배포: 실제 경기 20경기와 실전 중계 500건 이상 확보, 핵심 사건 80개 이상 및 규칙표 1:1 매핑, 1~2주 병행 비교 후 채택 여부 결정.

추가 한계: ID/시각이 없는 과거 기록은 정확한 사건 대응을 항상 복원할 수 없다. 이미 저장 과정에서 타순 기준으로 정렬되어 순서를 잃은 중계도 파서만으로 원래 순서를 복구할 수 없다. 이런 자료는 원본 대조와 수동 보정이 필요하다.
