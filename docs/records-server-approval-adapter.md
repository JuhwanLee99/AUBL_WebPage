# 서버 인증 어댑터와 실행 승인 계약

작성일: 2026-09-08

## 구현 범위

`functions/scoring_test_application.py`에 내부 callable 요청 어댑터를 추가했다. Firebase runtime이 이미 검증한 `req.auth`만 신뢰한다. 임의 JWT를 검증하는 기능이나 외부 endpoint를 추가한 것은 아니다.

- 일반 `admin` claim과 별개로 `scoringTestOperator === true`를 등록·중단의 필수 조건으로 사용한다.
- 예약의 UID는 인증 정보에서만 추출한다. payload에 UID·역할 등 허용되지 않은 필드가 들어오면 거부한다.
- 등록 시 disabled 상태, 승인자 일치, 서버 시각 기준 승인·만료 조건을 검사한다.
- 실행 명세에 배포 버전, 승인 근거 참조, 중단 책임자, 경기별 시나리오, 호출·업로드 한도, 정리 대상과 재조회 승인을 요구한다.
- 명세의 경기 목록·호출 한도·정리 namespace를 실행 등록 정보와 대조한다.
- 실행 범위·참여자·시간·허용 작업·실행 명세를 묶어 SHA-256 승인 해시를 생성한다. 서버 등록 시각과 실제 인증 주체도 보존한다.
- 등록 문서의 create에 승인 사본을 함께 포함하여 실행 등록과 승인 증거가 따로 저장되는 부분 성공을 피한다. 기존 문서 덮어쓰기나 자동 재승인은 제공하지 않는다.

## 승인 해시의 의미

해시는 승인한 내용을 식별하는 감사 값이며 전자서명이나 권한 검증의 대체물이 아니다. 해시 포맷은 `python-json-sort-ascii-v1`로 명시했다. 이후 기록 payload의 canonical serialization과 동일한 규격이라고 가정하지 않는다.

기존 내부 `create_disabled`는 이전 검증과 호환되도록 감사 정보 없이도 disabled 등록을 허용한다. 외부 요청용 새 어댑터는 완전한 명세와 감사 정보를 필수로 요구한다. 향후 활성화는 감사 정보 없는 등록을 거부하고 저장된 승인 사본·해시와 현재 실행 설정의 일치까지 확인해야 한다.

## 권한의 경계

전용 운영자 claim은 이 코드가 발급하지 않는다. 프로비저닝·회수·최근 토큰 반영 절차는 별도 구현 및 검증 대상이다. 전용 운영자는 전역 비상 중단을 수행할 수 있지만, 자동으로 테스트 경기 기록·공식 전환 권한을 얻지는 않는다. 개별 작업은 해당 실행의 참여자·역할·허용 목록 검사를 계속 거친다.

어댑터의 예약 응답은 여전히 예산 예약일 뿐 기록 저장 ACK가 아니다. 실제 writer는 커밋 시점에 실행 상태와 세션을 재검증해야 한다. 분당 요청 수와 업로드 바이트는 승인 명세에 추가했을 뿐 서버 집행은 아직 연결하지 않았다.

## 현재 상태 및 다음 검증

최초 구현 이후 아래 후속 검증을 실행했다. 이전 64건·10건 결과를 재사용한 것이 아니라 새 어댑터 검사와 기존 경계 회귀를 함께 재실행했다.

다음 검증 대상:

1. 익명·일반 관리자·전용 운영자 및 위조 payload 권한 행렬.
2. 불완전 명세, 시나리오·정리 범위·한도 불일치, 승인·만료 경계.
3. 동일 승인 내용의 해시 재현성과 참여자·시간·한도 변경 시 해시 변경.
4. Firestore 에뮬레이터에서 등록과 승인 사본의 동시 생성, 중복 등록 원본 보존.
5. 기존 정책 64건·예약 에뮬레이터 10건 회귀.

외부 API, 실행 활성화, 운영 배포는 추가하지 않았다. `production-test` 및 클라이언트 namespace 차단은 유지한다. 전체 상태는 `BLOCKED_BEFORE_LOGIN_BACKEND`다.

새 단위 테스트는 Firebase runtime 형태의 인증 스텁을 사용한다. 익명, 일반 관리자, 문자열 형태의 위조 claim, 승인자 불일치, payload UID 삽입, 불완전 명세와 시간 경계를 검증했다. 동일 명세의 해시 재현과 참여자·만료·예산·배포 버전 변경에 따른 해시 차이도 확인했다.

에뮬레이터는 `demo-aubl-scoring` 및 `127.0.0.1:8088` 강제 조건에서 실행했다. 테스트별 UUID 실행의 문서와 예약만 삭제하고, 재조회로 부재를 확인했다. 운영 데이터·권한 변경은 없다. 원본 로그는 `outputs/server-approval-adapter-2026-09-08/`에 보관했다.

실제 Firebase 로그인·토큰 검증·claim 발급 및 회수·외부 callable endpoint는 이번 검증 범위가 아니다. 분당 요청 제한, 업로드 예산 집행, 서버 외부 연결 격리 및 승인 해시를 확인하는 활성화 절차는 계속 미구현이다. 기록 writer·최종 봉인·공식 전환의 통합 완료로 판정하지 않는다.
