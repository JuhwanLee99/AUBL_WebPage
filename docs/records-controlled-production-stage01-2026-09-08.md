# 통제된 운영 테스트 준비: 0·1단계 구현 및 검증

작성일: 2026-09-08

## 판정

`BLOCKED_BEFORE_LOGIN_BACKEND` 유지. 이번 변경은 기준선 복구 및 환경 안전 경계의 일부 구현이다. `READY_FOR_CONTROLLED_PROD_TEST`가 아니며 실제 경기 적용 승인이 아니다.

운영 로그인, 배포, 운영 데이터 쓰기, 테스트 경기 생성, 공식 전환 활성화는 수행하지 않았다. Firestore 검증은 `demo-aubl-scoring` 프로젝트의 로컬 에뮬레이터에서만 실행했다.

## 구현 내용

| 영역 | 반영 내용 | 남은 제한 |

| Firebase 초기화 | 로컬 Auth·Firestore·Functions 연결, AppCheck 비활성화, 잘못된 기존 앱 및 HMR 설정 변경 거부 | 실제 Auth·Functions 에뮬레이터 통합 실행은 미실시 |
| 브라우저 경계 | 로컬 API 프록시 대상 고정 및 로컬 연결 CSP 적용 | 서버 내부 NAS·외부 API 호출까지 통제하는 경계는 아님 |

| 테스트 namespace | `scoringTestRuns` 아래 클라이언트 읽기·목록·쓰기를 전부 거부 | 관리자도 거부. 서버 승인 및 범위 지정 writer 연결 전까지 개방 금지 |

## 이번에 검증하지 않은 항목

- 실제 앱 라우트의 브라우저 E2E, 실제 모바일 기기의 입력·복구·재접속.
- 실제 Auth·Functions 에뮬레이터 조합, 서버 내부 네트워크 격리, NAS 직접 임포트 방어.
- 운영 인증·배포·접근 행렬 및 운영 namespace의 실제 저장·재조회.
- 기존에 제외된 실제 전체 RPC 장애 2건. 이번 테스트의 제외 0건이 이 과제를 해소한 것은 아니다.
- 전체 KBO 규칙 대응, 실제 경기 20개 및 실제 문자중계 500문장 회귀 자료.
- 다중 입력 영속 큐, ACK 대기 중 추가 입력, 원자적 분할 저장, 최종 커밋 봉인.

조항별 대응표의 필수 필드는 `sourceUrl`, `edition`, `retrievedAt`, `contentHash`, `clause`, `profile`, `expectedOutcome`, `implementation`, `testIds`, `reviewStatus`로 한다. 원문 확보 후 독립 기대값을 작성하고 정상·경계·모순 입력을 연결한다. 미구현 항목을 단순 미확정 입력으로 바꾸어 완료 처리하지 않는다.

## 이후 순서 및 완료 조건

1. 0단계 잔여: 전체 규칙집·개정·정정 증거를 확보하고 조항별 대응표를 고정한다. 실패·제외·정적 위험은 별도로 유지한다.
2. 1단계 잔여: 서버 실행 등록, UID·경기 허용 목록, 서버 시각 기준 만료, 호출 한도, 중단 제어 및 서버 내부 외부 연결 차단을 구현한다. 클라이언트 입력으로 저장 경로를 결정하지 않는다.
3. 사건 계약: 불변 선수·출전 구간 ID, 플레이 순서, 투수 책임, 판정·정정 대상과 버전, 경기별 규칙 프로파일을 고정한다.
4. 규칙·모달: 교체, 과거 어필과 후속 재생, 안전진루권·방해·득점 예외, 경기 종료·재개, 무실책 가상 이닝 및 결정 기록을 순차 연결한다.
5. 저장 경로: 기존 길이 기반 분리 저장을 다중 입력 IndexedDB 큐와 요청별 ACK로 교체한다. 불변 블록·manifest의 동일 revision만 공개하고 구형 writer로 자동 복귀하지 않는다.
6. 인증·공식 전환: 작성 세션과 `lockEpoch`, 최종 ACK·커밋 ID·해시 봉인, 관리자 원본 비교, NAS 직접 임포트 차단을 연결한다. 단순 15초 대기로 승인하지 않는다.
7. 사전 검증: 실제 앱·에뮬레이터·실제 자료·긴 경기·권한 행렬을 검증하고 기존 제외 항목까지 해소한다.
8. 운영 진입 준비: 기본 비활성 배포와 실행 명세를 준비한다. 프로젝트·API·UID·경기·호출 한도·버전·책임자·정리 대상을 사용자가 승인하기 전에는 실행하지 않는다.

최초 운영 테스트는 별도 namespace, 최대 3경기, 24시간 이하, 지정 참여자로 제한한다. 공개 일정·검색·공식 누적과 분리한다. 범위 밖 쓰기, 비참여자 노출, 유실·중복 또는 revision 불일치 발생 시 즉시 신규 쓰기를 중단하고 증거를 보존한다. 정리는 해당 실행이 생성한 데이터와 권한에만 한정한다.

필수 검증 실패·제외 0건, 알려진 필수 규칙 미구현 0건, 유실·중복·원본 노출·공식 통계 혼입 결함 0건일 때만 진입 상태를 변경한다. AUBL 규칙 프로파일 및 실제 AUBL 경기 적용 승인은 별도 후속 과제다.

## 상세 설계와 결정 근거

승인된 계획의 초기 분석, 대안 비교, 선택 이유, 주요 인터페이스, 영속 큐·ACK·분할 저장·공식 전환 계약은 [실시간 기록·문자중계 아키텍처 결정 문서](records-controlled-production-architecture-decisions.md)에 상세히 정리했다. 해당 문서는 확정 정책, 설계 계약, 후속 확정 항목과 실제 구현 현황을 구분한다. 설계 상세화만으로 현재 운영 진입 차단 상태를 변경하지 않는다.
