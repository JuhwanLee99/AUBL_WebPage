# 자책점 확인 상태와 운영 데이터 보호

## 범위

- 실시간 자책점 계산은 기존 휴리스틱을 유지하고 `estimated`로 표시한다. KBO 규칙에 따른 이닝 재구성 기반의 자책점 확정 엔진을 구현한 것은 아니다.
- `unconfirmed`: 확인 정보가 없거나 유효한 자책점 숫자가 없는 기록. 과거 숫자는 보존하지만 확정값으로 표시하지 않는다.
- `estimated`: 자동 추정값. 자책점과 ERA 모두 추정임을 표시한다.
- `confirmed`: 수기 입력 화면에서 기록원이 명시적으로 확인한 값. KBO 또는 외부 기관의 공식 인증을 의미하지 않는다.
- 자책점 값을 수정하면 확인 상태를 초기화한다. 자책점 또는 이닝 수정 시 저장된 ERA를 제거하여 오래된 파생값을 남기지 않는다.
- 경기 종료 자동 저장, 저장 데이터 정규화, 문자중계 통계, 투수 표, 실시간 CSV에 상태를 전달한다.
- 0아웃 ERA와 미확정 ERA는 숫자 0으로 만들지 않는다. 누락된 자책점도 확인된 0으로 취급하지 않는다.

## 테스트 및 운영 데이터 원칙

- `npm run test:scoring`의 새 테스트는 순수 함수와 메모리/JSON fixture만 사용한다. Firebase, 인증, 경기 저장 API를 호출하지 않는다.
- 이 단계에서는 운영 테스트 경기나 기록을 생성하지 않는다. 따라서 삭제 대상도 없다.
- 향후 운영 저장 연동 테스트가 필요하면 별도 `[테스트] 기록 엔진 검증` 경기만 사용하고 생성 ID를 추적한다. 기존 경기에는 쓰지 않는다.
- 테스트 후 해당 실행에서 만든 기록만 삭제한다. 삭제하지 못하면 테스트 표시를 유지하고 남은 ID와 사유를 보고한다. 운영 공식 통계/문자중계 노출 여부도 먼저 확인한다.

## 남은 범위

- 브라우저 수기 입력과 Firestore 저장/재조회 통합 검증.
- 확인자, 확인 시각, 근거와 정정 이력의 영구 감사 로그.
- KBO 자책점 규칙에 따른 이닝 재구성 및 투수 교체 시 책임 재산정.
- 실제 과거 경기와의 전체 집계 동치 검증 및 외부 공식 기록 화면의 별도 상태 정책.
