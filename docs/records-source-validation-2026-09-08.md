# 공식 원천 전환 기반 검증 기록

검증일: 2026-09-08

대상 설계: `docs/records-source-lifecycle.md`

## 안전 경계

- 운영 DB 저장, 운영 자료 삭제, 배포, 기능 플래그 활성화는 수행하지 않았다.
- Firestore 검증은 `demo-aubl-scoring`, loopback `127.0.0.1:8088` 에뮬레이터로 제한했다. 테스트 시작 시 호스트와 프로젝트가 다르면 실행을 거부한다.
- 테스트 경기 ID는 `LOCAL_TEST_SOURCE_*`이며 원본 데이터도 `LOCAL_TEST_*`, `PRIVATE_TEST_*`로 명시했다.
- 실제 Python 전환 함수의 외부 공식 API 조회는 `https://official-fixture.invalid` 응답으로 대체했다. 다른 URL 요청은 테스트가 차단한다. Firestore 트랜잭션은 실제 에뮬레이터에서 실행했다.
- 브라우저 테스트는 저장소의 Vite 설정과 운영 환경 파일을 읽지 않는다. 로컬 테스트 서버와 에뮬레이터 이외 요청을 차단한다.
- fixture는 테스트 종료 시 정리하며 에뮬레이터는 `emulators:exec` 종료 시 중지한다.

1. 문자중계의 공개 상태 오류 안내에 다시 접속하는 `onRetry`를 연결했다.

하네스 진입 경로와 앱 별칭 경로 분리는 수정했다. 이후 확인된 JSX 변환 누락 및 공식 화면의 오래된 기대값은 별도 승인 대상으로 분리했으며, 후속 실행 결과는 아래에 추가한다.

## 권한 검증 범위

- 익명, 일반 회원, 기록원, 이메일만 관리자처럼 보이는 계정, admin claim 관리자 등 5개 주체.
- 공식 전환 전 자체 core/feed/events 공개 읽기.
- 전환 후 비관리자 원본 GET 및 feed/events 목록 조회 거부.
- 전환 후 관리자 원본 읽기 허용, 관리자 포함 변경·삭제 거부.
- Atomic 스트림 및 영수증 원본 접근 제한, 소유자 재개 차단.
- 클라이언트의 공식 출처 문서 생성, 일정의 공식 플래그 변조, 공개 되돌리기 차단.
- 관리자 이슈 7개 원인 분류 및 4개 상태의 추가 허용.
- 이슈의 오래된 리비전, 다른 해시, actor 사칭, 다른 경기, 미허용 필드, 비정상 상태, 빈/과대 내용, 클라이언트 시각 거부.
- 이슈는 추가만 가능하며 수정·삭제는 거부.

## 실제 전환 트랜잭션 검증 범위

- 공개 원천·공식 점수 적용과 자체 필드 제거, 최초 보관본 생성.
- 보관된 자체 schedule과 기존 matchStates 내용 유지.
- 동일 리비전 재시도의 중복 적용 방지.
- 새 리비전 적용 시 최초 자체 보관본 유지 및 공식 리비전 이력 추가.
- 같은 리비전의 다른 본문 거부.
- 일정 리비전 불일치 시 부분 보관 없음.
- 진행 중 자체 기록 및 저장 후 15초 이내 전환 거부.
- 불완전한 보관 상태, 삭제된 경기, 기본 비활성 설정에서 전환 거부.

## 새 브라우저 검증의 경계

새 하네스는 실제 `useRecordSource`, `RecordSourceGate`, 관리자 비교 페이지, Firestore SDK/Rules, Python 전환 트랜잭션을 사용한다. 로그인 정보, 공식 API 응답, callable HTTP 전달부, 공유 Store의 일정 제공 부분은 테스트 대역이다.

따라서 이 검증을 실제 Firebase 로그인 또는 배포된 HTTPS callable의 종단 간 검증, 실제 NAS 연계 검증으로 부르지 않는다. 실제 DemoStore Provider 전체를 마운트하지 않으므로 Provider의 모든 이력 초기화·재접속 경합까지 검증한 것도 아니다.

desktop/mobile 각각 다음 8개 사례를 구성했다:

1. 비로그인 상태에서 참고 기록을 보다가 공식 전환되면 원본 화면 제거 및 원본 직접 조회 거부.
2. 기록원도 공식 전환 후 관리자 원본 접근 권한을 얻지 않음.
3. 관리자에게만 보관 기록 비교 링크와 원본 읽기 제공.
4. 관리자 확인란 → 실제 전환 → 차이 비교 → 이슈 저장 → 원본 중계 조회.
5. 공식 API 장애 중에도 고정 공식 스냅샷을 통한 관리자 비교 유지.
6. 경기 A에서 B로 이동했을 때 출처 응답 혼동 방지.
7. 오프라인에서 새 경기의 공식 문서 부재를 공개 허용으로 해석하지 않음.
8. 지원하지 않는 출처 문서 형식이면 자체 원본 표시 차단.

## 알려진 제외 항목과 다음 승인 조건

- 기존 HTTP/1 네트워크 게이트의 `actual all RPC outage`, `actual commit RPC outage` 2건은 gRPC/HTTP2와의 하네스 불일치가 알려져 있어 이번 실행에서 필터로 제외했다. 성공 또는 해결로 기록하지 않는다.
- NAS Admin SDK 프로젝션이 비공개 필드를 재노출하지 않는지, 기존 공식 통계 원천이 섞이지 않는지 확인해야 한다.
- 기존 실시간 저장의 마지막 입력 ACK 및 core/feed/events 분리 저장 경합은 이 테스트 통과만으로 해결되지 않는다.
- 실제 공개 문자중계 페이지 및 DemoStore Provider 전체를 포함한 인증/출처 전환 브라우저 검증은 별도 확장이 필요하다.
- 자동 전환 플래그는 계속 비활성으로 유지한다. 운영 전환 승인과는 별도 단계다.

## 후속 실행 1: 테스트 하네스 보완

사용자 승인 후 가상 진입 모듈을 TypeScript로 명시적으로 JSX 변환하고, 공식 화면 회귀 테스트를 자책 미확정/확정 두 조건으로 나눴다. 미확정에서는 ERA를 표시하지 않고, 확인된 자책 1점/5아웃에서는 5.40과 기록원 확인 표시를 검증한다.

- 공식 화면 회귀: 15/15 통과.
- 새 원천 E2E: 16건 실행, 14건 통과, 2건 실패.
- 실패 2건은 desktop/mobile의 관리자 이슈 등록 단계다. 공식 전환과 비교표 표시까지 진행했으나 테스트의 `getByLabel('원인 분류', { exact: true })` 선택자가 입력을 찾지 못했다.
- 실패 스크린샷에서 실제 원인 분류 입력과 나머지 이슈 폼이 표시됨을 확인했다. 제품 UI를 삭제하거나 조건을 완화하는 대신 테스트 선택자만 보완하도록 별도 승인 요청했다.
- 이 단계에서는 이슈 저장과 원본 중계 추가 조회가 아직 E2E로 통과한 것이 아니다.
