# 구조화 주루 매트릭스 구현

기준일: 2026-09-08. 이전 단계의 후보 검수/상태 재생에 이어 실제 주루 입력을 한 사건으로 저장하는 경로를 추가했다.

후속 [안타 입력·책임 실점 연결](records-hit-integration.md)에서 안타/홈런 액션과 저장된 책임 투수의 집계 반영을 확장했다. 아래 남은 작업은 매트릭스 최초 구현 당시 기준이며 최신 진행 범위는 후속 문서를 참고한다.

## 사용 위치

기록원 페이지의 `주자 액션 바로가기`에서 **전체 주자 함께 기록**을 누른다. 각 주자의 결과, 사유, 발생 순서를 선택하고 미리보기의 득점/아웃을 확인한 뒤 **한 사건으로 저장**한다.

- 결과: 정지, 다음 루 진루, 홈 도달, 아웃.
- 사유: 진루, 도루 성공, 도루자, 견제사, 폭투, 포일, 기타 주루.
- 아웃 종류: 태그/일반 주루 아웃, 포스, 공과·리터치 어필.
- 발생 순서: 변경되는 주자 결과와 타자 아웃에 중복 없는 순서를 지정한다. 정지한 주자의 순서는 계산하지 않는다.
- 책임 투수: 기존 베이스 책임 정보를 표시하고 주자를 따라 이동시킨다. 기록이 없으면 미확인으로 유지한다.
- 동시에 타자가 1루 도달 전에 아웃된 일반 플레이는 타자 아웃 항목으로 함께 입력할 수 있다. 이 경우 타순과 볼카운트도 한 번만 갱신한다.
- 타점은 일반 타자 아웃을 함께 기록할 때 기록원이 지정한다. 인정된 득점 수를 초과할 수 없고, 주자만의 플레이에 타점을 부여하지 않는다.
- 안타·출루·희생타·삼진, 실책 판정, 투구 판정은 기존 전용 입력을 사용한다. 매트릭스는 투구 중 볼/스트라이크 판정을 대신하지 않는다.

## 한 번에 적용하는 경로

`RunnerMatrixButton → recordRunnerPlay → resolveRunnerPlay → applyScoringEvent → 이벤트/중계/스냅샷`

기존 아웃 액션 뒤에 진루 액션을 연속 호출하는 방식과 별도로, 매트릭스 경로는 전체 결과를 먼저 검사한 다음 단일 reducer 액션과 단일 PlayEvent로 저장한다. 실패하면 주루·점수·정상 이벤트를 변경하지 않고 기존 반려 내역 경로로 사유를 남긴다. 기존 undo/redo의 한 단계가 매트릭스 사건 하나에 해당한다.

`PlayEvent.runnerPlay` 버전 1에 다음을 저장한다.

| 항목 | 내용 |
| --- | --- |
| input.id | 중복 입력 방지용 ID |
| input.expected | 입력을 시작한 경기 ID, 이닝/공수, 점수/카운트, 베이스, 책임 투수, 타순 |
| input.movements | 주자 식별자, 출발/도착 루, 사유, 발생 순서, 아웃 종류 |
| input.batterOut | 함께 기록한 타자 아웃의 발생 순서 |
| input.note / rbi | 판정 메모, 명시한 타점 |
| movements | 책임 투수와 홈 도달 인정/무효 사유를 포함한 확정 결과 |
| runs / outsAdded / endedHalf | 인정 득점, 추가 아웃, 공수 교대 여부 |
| runsAllowedBy / unassignedRuns | 책임 투수별 실점과 책임 미확인 실점 |

주자 ID는 기존 시스템의 이름/등번호 식별자를 사용한다. 리그 전체에서 유일한 별도 선수 UUID 체계로 전환한 것은 아니다. 저장 복구 시 입력 스키마를 검사하고 파생 결과를 재계산하며, 손상된 자료는 수동확인 대상으로 둔다.

## 검증과 규칙 적용 범위

공식 근거: [KBO·KBSA 2025 공식야구규칙 5.08(a), 본문 46~48쪽](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2025_%EC%95%BC%EA%B5%AC%EA%B7%9C%EC%B9%99.pdf#page=69). 판정 종류 자체는 기록원이 입력하며, 아래 계산은 입력한 판정과 발생 순서에 따른다.

| 사건 | 처리 | 회귀 테스트 |
| --- | --- | --- |
| 포스 제3아웃 | 앞선 홈 도달도 무효 | force third out cancels an earlier home crossing |
| 태그 제3아웃 전 홈 도달 | 득점 인정 | home crossing before a tag third out counts |
| 태그 제3아웃 후 홈 도달 | 득점 무효 | home crossing after a tag third out does not count |
| 선행 주자의 공과/리터치 어필이 제3아웃 | 후위 주자의 득점 무효 | preceding-runner appeal third out cancels following runs |
| 후위 주자에 대한 어필이 제3아웃 | 먼저 홈에 도달한 선행 주자의 득점 유지 | appeal against a trailing runner does not cancel earlier leading-runner score |
| 타자의 1루 도달 전 아웃이 제3아웃 | 해당 플레이 득점 무효 | batter out before reaching first as third out cancels all runs |

다음 입력은 반려한다.

- 동일 루에 복수 주자 배치, 주자 누락/중복/신원 불일치.
- 최종 배치 또는 홈 도달 순서에 나타나는 선행 주자 추월.
- 중복 발생 순서, 잘못된 아웃 종류, 소수/범위 밖 순서.
- 남은 아웃보다 많은 아웃, 역방향 귀루, 변경 없는 사건.
- 입력 중 경기 ID·카운트·점수·타순·주자·책임 투수가 변경된 경우.
- 득점 수를 초과한 타점 또는 주자 단독 사건의 타점.

같은 입력 ID를 다시 전달하면 정상 이벤트에 이미 존재하는지 확인해 재적용하지 않는다. UI가 열린 뒤 기록 권한이나 경기 상태가 바뀌어도 저장을 제한한다.

## 문자중계와 CSV

한 사건의 문자중계 행은 지정한 발생 순서대로 추가한다. 인정된 홈 도달에만 `득점`이라는 표현을 사용한다. 무효 홈 도달은 `홈 도달 무효`로 표기하여 기존 문자열 기반 득점 집계가 이를 득점으로 세지 않도록 한다.

기록원/점수관 CSV의 `구조화 주루 기록` 섹션에 주자, 출발/결과, 순서, 사유, 책임 투수, 홈 도달 판정, 타자 결과, 타점, 판정 메모를 출력한다. 자동 파서 후보가 직접 입력한 구조화 기록을 덮어쓰지 않으며, 사용자가 재분류한 사건에는 이전 주루 전이를 검증 근거로 물려주지 않는다.

## 남은 작업

1. 기존 안타/희생타/실책/낫아웃 입력도 같은 구조화 사건과 주루 매트릭스를 사용하도록 전환. 기존의 연속 아웃·진루 액션 경로는 아직 유지된다.
2. 추가 어필로 유리한 제4아웃 선택, 포스 상태 해제, 이미 홈에 도달한 주자에 대한 사후 어필 등 상세 판정 모델 확장.
3. 경기 종료 재해석 보정의 서버 저장, 기록원/수정 시각/버전 충돌/롤백 관계 저장.
4. 저장한 `runsAllowedBy`를 공통 투수 집계에 연결. 자책점은 이 단계에서 자동 확정하지 않는다. 기존 선수 집계 전체가 구조화 사건 기반으로 전환된 것은 아니다.
5. 주자 책임이 누락된 과거 데이터 보정 및 실전 경기 회귀 검증.
