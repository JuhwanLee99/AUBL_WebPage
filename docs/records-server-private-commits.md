# 비공개 manifest·영수증·head 원자적 커밋

작성일: 2026-09-08

## 구현 범위

`functions/scoring_test_commits.py`에 내부 커밋 서비스를 추가했다. `SCORING_TEST_COMMIT_ENABLED`가 명시적으로 true가 아니면 시작하지 않는다. 실행 활성화나 이 플래그 설정은 수행하지 않았다.

manifest는 state·feed·events·stats 네 종류를 모두 요구한다. 순서가 있는 descriptor 목록, 스키마·규칙 프로파일·엔진·projection 버전, 경기 ID를 해시로 고정한다. 제한은 descriptor 4~64개, 단일 블록 128KiB 이하, 논리적 합계 8MiB 이하다. 전체 경기의 최종 용량 정책이 아니라 첫 내부 커밋 구현의 방어 상한이다.

## 원자적 처리

1. 실행 인가·승인 해시와 현재 작성 세션·epoch를 검사한다.
2. 요청 ID·payload 해시·입력 순번 범위·expected revision의 바인딩을 확인한다.
3. 처음 들어온 요청은 현재 head revision과 대조한다. 같은 작성 세션의 입력 순번은 직전 마지막 순번 다음부터 이어져야 한다. 새 인계 세션의 로컬 순번은 1부터 시작한다.
4. 참조 블록을 같은 트랜잭션에서 읽고 경기 범위·크기·내용 해시·content address를 검증한다. 누락·다른 경기·변조 블록은 거부한다.
5. 불변 manifest, 요청 영수증, 새 head를 하나의 트랜잭션으로 반영한다. 실패하면 새 head를 노출하지 않는다.

저장 경로는 `scoringTestRuns/{runId}/scoringHeads/{matchId}`와 그 아래 `manifests`, `receipts`다. 기존 namespace 클라이언트 차단을 그대로 적용하며 공개 일정·경기 원본 경로에 쓰지 않는다.

## 재시도와 ACK

동일 요청은 바인딩이 모두 같을 때 기존 영수증을 반환한다. 다른 내용의 요청 ID 재사용은 거부한다. ACK에는 요청 순번 범위, payload hash, 확정 revision·commit ID가 포함된다. 최신 head revision은 별도 `headRevision`으로 반환하여 과거 ACK를 최신 상태 승인으로 오인하지 않게 한다.

응답 유실 재시도도 현재 실행 권한과 작성 세션을 먼저 검사한다. 인계 이후 이전 세션의 영수증 복구를 허용하는 별도 관리자 조회 API는 아직 없다.

## 보장하지 않는 내용

이 서비스는 **비공개 저장 구조의 원자성**만 구현한다. 블록 내용을 야구 사건·중계·집계 스키마로 해석하거나 서로 같은 경기 상태인지 의미적으로 검증하지 않는다. 네 종류의 블록이 있다는 사실만으로 올바른 점수·아웃·문자중계라고 판정하지 않는다.

규칙 프로파일의 최초 값은 아직 승인된 경기 계약과 대조하지 않고, 이후 커밋에서 같은 값을 유지하도록만 제한한다. 입력 순번 범위가 실제 사건 입력 목록과 일치하는지 검증하는 사건 계약도 필요하다. 별도 커밋 호출의 rate limit, 실제 모달 Provider·IDB 큐 연결, 관전자 조회, 최종 봉인·UniquePlay 전환은 미구현이다.

manifest/head가 생겨도 `status: private`이며 서비스에 공개하지 않는다. 운영 활성화를 승인하는 근거로 사용할 수 없다.

## 검증 상태와 다음 단계

최초 구현 이후 아래 정상 커밋·재조회, 누락·변조·다른 경기 블록, 같은 ID 다른 payload, 순번 누락, 동시 revision 충돌, 인계 후 이전 세션 및 동일 요청 재호출 검증을 실행했다. 실제 네트워크 ACK 유실 주입은 아직 수행하지 않았다.

운영 접근·배포 없이 `BLOCKED_BEFORE_LOGIN_BACKEND`를 유지한다.

|---|---|---|

확인한 결과:

- 정상 커밋은 private head, manifest, 영수증으로 저장·재조회되며 동일 요청 재호출은 새 revision을 생성하지 않는다.
- 두 번째 커밋 이후 첫 요청을 재호출하면 과거 `committedRevision`과 최신 `headRevision`을 구분하여 반환하고 최신 head는 유지한다.
- 누락·변조·다른 경기 블록과 순번 누락은 거부되며 head·manifest·영수증이 생성되지 않는다.
- 같은 요청 ID의 다른 manifest는 거부한다.
- 같은 revision의 동시 요청은 한 건만 커밋되고 나머지는 충돌한다. manifest·영수증도 각 한 건만 남는다.
- 인계 후 이전 세션 커밋은 거부하며 새 세션은 허용한다.
- 별도 커밋 기능 플래그의 비활성 상태에서는 저장하지 않는다.

테스트에서 생성한 manifest·영수증·head 및 기존 세션·인계·블록·예약·실행 문서를 삭제하고 해당 범위에서 재조회로 부재를 확인했다. 로그·요약은 `outputs/server-private-commits-2026-09-08/`에 보관한다.

커밋 테스트의 블록은 저장 구조를 확인하는 합성 바이트다. 실제 야구 상태·문자중계·통계의 의미적 동치나 전체 경기 재현을 검증한 것이 아니다. 재시도 검증은 동일 요청 재호출이며 실제 RPC 응답 유실·브라우저 큐 복구를 주입한 검증을 대체하지 않는다. 커밋 중 서비스 중단·저장 장애 주입, 장기 반복 경합과 긴 경기 부하도 별도 과제다.

다음 저장 계층 과제는 동일 revision의 비공개 재구성 조회, 최종 커밋 봉인 및 사건 의미 검증과의 연결이다. 관전자 공개·Provider writer 교체·운영 활성화는 계속 차단한다.
